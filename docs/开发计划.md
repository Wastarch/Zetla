## 0. 总体节奏

```
M0 = MVP 完整闭环（≈2–3 周） → M1 创作增强（≈2 周） → M2 绘图组件 + 深度编辑（≈2–3 周） → M3/M4 按需
```

**M0 = MVP**：完成「打开项目 → 新建 TeX 文档 → 编写代码 → 一键 XeLaTeX 编译 → 查看 PDF 预览」完整闭环；**只保留核心链路**，砍掉所有非必要功能（✅必做 / ❌后置清单见 `docs/MVP.md` 与开发文档 §0.1）。

原则（沿用开发文档 §11）：

1. **切片提交**：每个任务是一次可独立运行验证的小切片，跑通再下一个，不攒大 diff。
2. **只做核心链路**：M0 只交付 MVP 必做项（项目树、多标签编辑器、一键编译+报错跳转、PDF 预览、三栏布局、基础 IPC）；**环境引导（含 TeX 自动安装）由用户指令提前进 M0-15**，R5/R6/R7/绘图等仍进 M1/M2。
3. **类型即协议**：`src/types/` 与 Rust struct 一一对应，改一边必同步另一边。
4. **每轮 Linux/WSL 过一眼**：WebKitGTK 是渲染差异集中区，提前拦截。
5. **真实数据自测**：M0 收尾按开发文档 §12.1 MVP 验收清单跑全流程，错误定位用真报错文档，不绕过验收。
6. **分工（2026-10-20 起，长期约定）**：agent 负责 `npm run build`（涉 Rust 时 `cargo test`）+ `tauri dev` 启动无报错级自检，随后同步文档（看板/开发文档）；**冒烟测试与 git 提交由用户本人完成**，因此看板行在用户提交前不写提交哈希。每切片均如此。

### 编译链公共约定（M0-9/11/12 共用，M0-3 已定死，不改）

**数据结构**（与 `src/types/compile.ts` 对齐，Rust 侧 `#[serde(rename_all = "camelCase")]`）：

```
TexDistInfo  { found, distribution?, version?, engines[], recommended? }
CompileProgress { stage, pct, current }
TexError     { file, line, col?, raw, readable, fix?, hint? }
CompileResult { status, pdfPath?, errors[], passes, durationMs }
```

**事件名**（Rust 字符串必须与前端 `src/ipc/events.ts` 的 `RustEvents` 完全一致）：

- `compile_progress` — stage: prepare / running / parsing / done，current: 实时日志行
- `compile_finished` — CompileResult 负载，经 `AppHandle.emit(...)` 推送

**Rust 依赖引入计划**：

| crate | 引入切片 | 用途 |
|---|---|---|
| `which` | M0-3 ✅ | 跨平台 PATH 查找可执行文件 |
| `tokio`（process/macros/time） | M0-9 ✅ | 异步 spawn 子进程、流式读 stdout/stderr |
| `notify` | M0-9a | 项目目录变更监听（防抖后刷新资源树） |
| `regex` | M0-11 | 日志解析 |

**前置条件**：

- M0-12 错误定位原计划做"最小只读预览"，因编辑壳（M0-4~6）提前完成，届时直接用正式编辑器的 `gotoLine`，**只读预览方案作废**
- M0-9 的编译按钮/编译状态栏在 M0-6 已放好占位，M0-9 直接接通

**P0 简化取舍**：
