## 0. 总体节奏

```
M0 = MVP 完整闭环（≈2–3 周） → M1 创作增强（≈2 周） → M2 绘图组件 + 深度编辑（≈2–3 周） → M3/M4 按需
```

**M0 = MVP**：完成「打开项目 → 新建 TeX 文档 → 编写代码 → 一键 XeLaTeX 编译 → 查看 PDF 预览」完整闭环；**只保留核心链路**，砍掉所有非必要功能（✅必做 / ❌后置清单见 `docs/MVP.md` 与开发文档 §0.1）。

原则（沿用开发文档 §11）：

1. **切片提交**：每个任务是一次可独立运行验证的小切片，跑通再下一个，不攒大 diff。
2. **只做核心链路**：M0 只交付 MVP 必做项（项目树、多标签编辑器、一键编译+报错跳转、PDF 预览、三栏布局、基础 IPC）；**环境引导（含 TeX 自动安装）由用户指令提前进 M0-15**，R5/R6/R7/绘图等仍进 M1/M2。
3. **类型即协议**：`src/types/` 与 Rust struct 一一对应，改一边必同步另一边。
4. **每轮 Linux/WSL 过一眼**：WebKitGTK 是渲染差异集中区，提前拦截。
5. **真实数据自测**：M0 收尾按开发文档 §12.1 MVP 验收清单跑全流程，错误定位用真报错文档，不绕过验收。
6. **分工（2026-10-20 起，长期约定）**：agent 负责 `npm run build`（涉 Rust 时 `cargo test`）+ `tauri dev` 启动无报错级自检，随后同步文档（看板/开发文档）；**冒烟测试与 git 提交由用户本人完成**，因此看板行在用户提交前不写提交哈希。每切片均如此。

### 编译链公共约定（M0-9/11/12 共用，M0-3 已定死，不改）

**数据结构**（与 `src/types/compile.ts` 对齐，Rust 侧 `#[serde(rename_all = "camelCase")]`）：

```
TexDistInfo  { found, distribution?, version?, engines[], recommended? }
CompileProgress { stage, pct, current }
TexError     { file, line, col?, raw, readable, fix?, hint? }
CompileResult { status, pdfPath?, errors[], passes, durationMs }
```

**事件名**（Rust 字符串必须与前端 `src/ipc/events.ts` 的 `RustEvents` 完全一致）：

- `compile_progress` — stage: prepare / running / parsing / done，current: 实时日志行
- `compile_finished` — CompileResult 负载，经 `AppHandle.emit(...)` 推送

**Rust 依赖引入计划**：

| crate | 引入切片 | 用途 |
|---|---|---|

**数据模型**（`src/modules/table/tableModel.ts`，纯函数、无框架依赖）：

```ts
type HAlign = "l" | "c" | "r";
interface Cell {
  text: string;
  colSpan?: number;   // ≥2 → \multicolumn
  rowSpan?: number;   // ≥2 → \multirow（需 multirow 宏包）
  raw?: boolean;      // 该格关闭转义（写原生 LaTeX，如 $\alpha$）
  align?: HAlign;     // 单元格级覆盖（colSpan>1 时生效）
}
interface TableModel {
  rows: number; cols: number;
  cells: Cell[][];        // rows×cols；被合并覆盖的位置标 covered
  aligns: HAlign[];       // 每列默认对齐
  header: boolean;        // 首行表头：生成时加 \midrule 分隔
  caption: string; label: string;
  numbered: boolean;      // false → table*
  placement: string;      // 默认 "htbp"
  style: "booktabs" | "grid" | "plain";
  width: "auto" | "full"; // full → tabularx + X 列
```

**代码生成**（`tableGen.ts`）：

```latex
\begin{table}[htbp]
  \centering
  \caption{实验结果}
  \label{tab:results}
  \begin{tabular}{lcr}
    \toprule
    名称 & 数量 & 占比 \\
    \midrule
    A & 12 & 3.5\% \\
    B & 8 & 2.3\% \\
    \bottomrule
  \end{tabular}
\end{table}
```

- **三线表**（`booktabs`）：`\toprule` / 表头后 `\midrule` / `\bottomrule`；无表头只有上下两条。
- **样式三选**：`booktabs`（默认）/ `grid`（`\hline` + 列规格加 `|`）/ `plain`（无横线）。
- **列规格**：`aligns` 拼 `lcr`；`width:"full"` 改 `tabularx` + `{\linewidth}` + `X` 列。
- **合并**：`\multicolumn{n}{c}{文本}`；`\multirow{m}{*}{文本}`；叠加时 `\multicolumn{n}{c}{\multirow{m}{*}{文本}}`。
- **转义三档**（默认 `smart`，单元格级 `raw` 覆盖）：

| 模式 | 处理 |
|---|---|
| `smart`（默认） | 转义 `& % # _ { }`；保留 `$ ^ ~ \` 原样 → 单元格内可直接写 `$x^2$`、`\textbf{}` |
| `full` | 额外转义 `$ ^ ~ \`（纯文字表格用） |
| `off` | 全原样 |

- **编号**：`numbered=false` → `table*`；`placement` 默认 `[htbp]`；`label` 默认 `tab:` + slug（复用 M1-7 `slugify` 口径，取 caption 或文件名）。
- **宏包提示**：生成前检测活动文档是否含 `\usepackage{booktabs|multirow|tabularx}`，缺失 → 面板底部**非阻断提示** + 「插入到导言区」按钮（定位 `\begin{document}` 前插入；找不到位置只提示）。**不自动改导言区**，避免破坏模板。
- **插入落位**：`insertSnippetSelect(code, selFrom, selTo)` 把光标置于 `\caption{}` 内；设置可选「插入后聚焦首个单元格」。插入前保证块前后至少一个空行（同 M1-7 口径）。

**反向解析与安全覆盖**（`tableParse.ts`）：

- **定位**：从光标向前找最近 `\begin{tabular}`（花括号配对扫描），向后配 `\end{tabular}`；外层若有 `\begin{table}` 一并取 `\caption`/`\label`。只做表格子集解析，不引通用 LaTeX 解析器。
- **切分**：按**顶层** `\\` 切行、顶层 `&` 切格（跳过花括号内与 `\&`）；剥离 `\toprule/\midrule/\bottomrule/\hline/\cline/\cmidrule`；识别 `\multicolumn`/`\multirow` 反推 `colSpan/rowSpan`。
- **安全覆盖**：解析成功记录 `{ from, to, fingerprint }`（原片段 djb2 哈希）。点「更新表格」时校验指纹，不一致 → 拒绝并给两选项「另插入一份」/「放弃」，**绝不静默覆盖**源码。解析失败 → toast「光标处未找到可编辑的表格」，面板保留原网格。

**设置项**（`AppSettings.table` ↔ Rust `AppConfig.table`，camelCase）：

```ts
table: {
  style: "booktabs" | "grid" | "plain";  // 默认 booktabs
  numbered: boolean;                     // 默认 true
  placement: string;                     // 默认 "htbp"
  captionPrefix: string;                 // 默认 ""
  labelPrefix: string;                   // 默认 "tab:"
  escape: "smart" | "full" | "off";      // 默认 smart
  headerRow: boolean;                    // 新表格默认带表头

}
```

## M1-14 BibTeX 参考文献支撑（科研写论文基础能力）

> 2026-10-26 用户指令：补齐科研用户最大短板——BibTeX 引用，使 Zetla 从「尝鲜」具备「日常写论文」的基础能力。
> 验收口径：能正常写带参考文献的中文/英文期刊论文。

### 范围（对齐用户 7 项清单）

7. 配套修复：长文档下编辑器解析性能优化

### 架构决策（关键）

- **纯前端，零 Rust 改动**：bib 解析/索引在 TS 侧（`src/modules/reference/`），复用现有 `useBuffersStore`/`useProjectStore`/`jump.ts` 与 CM6 补全·悬停·lint 机制；不新增 Tauri command、不改 `tauri.conf.json`、不引入新 crate。
- **不写完整 BibTeX AST**：轻量正则/状态机提取 `@type{key, field}` 的 key 与 author/title/year，够用即可（开发文档 §3.4-C 规划的 Rust `get_symbol_index` 仍可作为后续增强，不在本期）。
- **索引缓存 + 防抖**：引用数据集中在 `useReferenceStore`，补全/悬停/lint 只读缓存，不在每次按键全量重解（直接服务第 7 项性能诉求）。

### 数据层 · M1-14a（src/modules/reference/）

- `bibParser.ts`：`BibEntry { key, type, line, fields, author, title, year }`。解析 `@type{key, field = {…} 或 "…", …}`，处理嵌套大括号、多条目；`@comment/@string/@preamble` 忽略内容仅占位。author 归一化为 `Last, Last2` 或 `F. Last et al.`；year 取 `year` 字段去花括号。
- `useReferenceStore.ts`（zustand）：
  - `bibFiles: { path; entries: BibEntry[] }[]`、`keyIndex: Map<string, {file; line; entry}[]>`（同 key 跨文件归并，用于重复检测）、`duplicateKeys: string[]`。
  - `initFromProject()`：读 `useProjectStore.tree` 递归收集 `.bib` 路径（tree 为嵌套 `nodes`）。
  - `reloadFile(path, content?)`：content 优先取已打开 buffer，否则 `projectApi.readFile` 从磁盘读。
  - `importBib(srcPath, targetDir?)`：复制到项目根（或 `refs/`，默认根），随后被自动发现。
  - 触发时机：项目打开 / tree 变化 → 重建 bib 列表；`.bib` 保存或外部变更（`watch_project` 事件）→ debounce 300ms 重解该文件；打开的 `.bib` buffer 内容变化 → 防抖重解。`recompute()` 重算 `keyIndex`/`duplicateKeys`。

## M1-15 项目管理（整体方案：多项目 / 项目设置 / 生命周期）

> 2026-10-27 用户指令：把「项目管理」整体方案并入 M1（含多项目+欢迎页 / 项目内设置面板 / 生命周期+模板库管理），写入开发计划。
> 目标：当前 Zetla 仅「打开一个文件夹 = 一个项目」，无最近项目、无欢迎页、无项目切换、无项目级设置 UI、无生命周期管理。本组补齐这一管理层，使 Zetla 从「单次写稿」具备「多项目管理」的日常能力。

### 范围（三支柱 A / B / C）

- **A 多项目 + 欢迎页**：项目注册表（最近/置顶/归档）、启动欢迎屏、项目切换器。
- **B 项目内设置面板**：把 `.ltex/config.json` 的引擎/主文件/输出目录/排除规则/图片目录/名称描述做成可视化设置 UI（扩展 M1-7 已有的 `ProjectSettingsDialog`）。
- **C 生命周期 + 模板库管理**：重命名/归档/删除/导出项目；模板库浏览与「另存为模板/导入自定义模板」（自 M3 拉回）。

### 架构决策（关键）

- **单活动项目 + 全局注册表（本期）**：沿用「一次只开一个项目」模型，新增 `AppConfig.recent_projects` 记录已知项目；**真正的多根工作区（同时开 N 个项目、各自树/标签/编译）留 P2**，本期只以**绝对路径作为 `projectId`** 埋维度，不实现并发多根（对齐编译计划「多项目并发放 M1+」）。
- **类型即协议**：所有新增 struct 与 `src/types/*.ts` 一一对应、camelCase、Rust 侧 `#[serde(rename_all = "camelCase", default)]`；改一边必同步另一边。
- **命令三处注册**：`commands/<域>.rs` + `lib.rs` 注册 + `src/ipc/invoke.ts` 补签名。
- **`exclude` 仅过滤资源管理器树**：不影响编译产物展示，也不影响 M0-9a 的 `notify` 监听（排除项仍在磁盘）。
- **未做项置灰 + tooltip** 标注接通切片（沿用 MVP 口径）。
- 引擎优先级保持 M1-3 口径：设置页显式 > `.ltex/config.json` > xelatex。
- 欢迎页 vs 「恢复上次项目」开关：恢复开 → 启动直进项目；否则 → 进欢迎页。

### 数据层

**项目注册表（全局，落 `AppConfig`）** —— 新增字段 `recent_projects: Vec<ProjectEntry>`（上限 ~20，serde default 空；`config.rs` 补 `normalize` + 单测，沿用既有 `AppConfig` 风格）：
