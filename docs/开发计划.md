# LaTeX 工作台 · 开发计划

> 依据：`docs/开发文档.md` v0.3（技术方案）
> 仓库起点：Tauri 2 + React 19 + Vite 8 初始模板已可运行（commit `64f8be3`），依赖已装齐（`@uiw/react-codemirror`、`codemirror-lang-latex`、`fabric`、`pdfjs-dist`、`zustand`），业务代码为零
> 更新日期：2026-10-20

---

## 0. 总体节奏

```
M0 内核+编辑壳（≈2–3 周） → M1 最小闭环（≈2–3 周） → M2 绘图组件（≈1–2 周） → M3/M4 按需
```

原则（沿用开发文档 §11）：

1. **切片提交**：每个任务是一次可独立运行验证的小切片，跑通再下一个，不攒大 diff。
2. **先立闭环**：优先做"编译 → 看结果"链路（这是留存核心），再补外围模块。
3. **类型即协议**：`src/types/` 与 Rust struct 一一对应，改一边必同步另一边。
4. **每轮 Linux/WSL 过一眼**：WebKitGTK 是渲染差异集中区，提前拦截。
5. **真实数据自测**：错误定位用真报错文档、模板用真论文结构，不绕过验收。

## M0 · 内核 + 编辑壳

> 目标：能新建项目、能编辑、能编译出 PDF（命令行级），暂无花哨 UI。

### M0-1 基础设施骨架（半天）

- 建目录：`src/{editor,core,modules,ipc,types}`、`src-tauri/src/{compile,template,project,fsdoc,symbols}.rs`
- `src/ipc/`：类型安全的 `invoke` 封装 + Tauri `listen` 封装
- `src/types/`：`TemplateManifest`、`TexError`、`CompileResult`、`SymbolIndex`、`FileDoc` 等，与 Rust struct 字段一一对应
- 前端事件总线：zustand store + 轻量 `bus.emit/on`，事件命名 `compile:progress`、`compile:done`、`file:changed`…
- ✅ 验收：`npm run tauri dev` 正常，一个测试 command 往返通

### M0-2 文档模型 · 持久层（1–2 天）

- Rust：`read_file`（自动探测 UTF-8/GBK，返回 `{content, encoding, eol}`）、`write_file`（**原子写**：临时文件 + rename，保持原 EOL）、`revert_file`
- 配合 `tauri-plugin-fs` 权限配置（capabilities）
- ✅ 验收：打开一个 GBK + CRLF 的老 `.tex` → 不乱码；保存后编码/换行不被破坏

### M0-3 编译引擎 · 发行版检测 ✅

- `detect_tex_distribution()`：PATH 探测 `xelatex/latexmk`，Windows 额外查 MiKTeX 安装目录
- ✅ 已完成：见 `docs/开发/M0-3编译引擎.md`（后续多遍编译/日志解析/错误定位重编号为 M0-9/10/11）

### M0-4 编辑器核心（1–2 天）

- `@uiw/react-codemirror` + `codemirror-lang-latex`：LaTeX 高亮、行号、括号配对、自动缩进、查找替换、折叠（basic-setup）
- 打开文件：`plugin-dialog` 选文件 → `read_file`（GBK 不乱码）→ 编辑 → Ctrl+S `write_file` / 另存为
- 程序化跳转 `gotoLine`（为 M0-11 错误定位与 M3 synctex 铺路）
- ✅ 验收：打开 GBK 老文档不乱码、编辑保存、重开内容正确

### M0-5 多文件标签页（1–2 天，纯前端）

- 每文件独立 `EditorState`（撤销栈独立）、标签切换/关闭、脏标记 `●`、关闭前未保存提示
- ✅ 验收：多文件来回切换无状态串扰、脏文件关闭有提示

### M0-6 项目树 + 状态栏（1–2 天）

- **前置小块**：`scan_project(path)` 最小版（walkdir 扫树 + `\documentclass`/`main.tex` 主文件启发式；读 config 完整版在 M0-8）→ 新增 `walkdir` 依赖
- 左侧树点击打开到标签；状态栏：当前文件/脏状态/编码 EOL 只读展示/编译状态占位
- 工具栏：编译按钮**禁用占位**（M0-9 接通）、新建（M0-7 接通）
- notify 外部变更监听顺带接上（`file_changed` → 重载提示）
- ✅ **里程碑：编辑壳跑起来**，日常写作可用

### M0-7 模板引擎 + 新建向导（2–3 天）

- `template.rs`：manifest schema（开发文档 §5.2）、`<%= var %>` 约 30 行渲染器（**禁用 `{{}}`**，避开 LaTeX 大括号）、必填校验
- 命令：`list_templates` / `get_template` / `create_project`（建目录 → 渲染 → 复制 assets → 写 `.ltex/config.json`）
- 内置模板 3 个：`thesis-cn`（多文件）、`resume-cn`（单文件）、`beamer-cn`，放 `src-tauri/templates/`
- 新建向导：模板选择 → 按 `variables[].type` 动态渲染表单 → 目标路径 → 创建 → 打开项目
- 完整版 `scan_project` 读 `.ltex/config.json` 定主文件（与模板衔接）
- ✅ 验收：向导建论文项目 → 树里出现结构 → 打开编辑；单文件模板不生成多余目录

### M0-8 项目管理（1 天）

- notify 监听补全（M0-6 已接则只补细节）、`clean_aux`、主文件回退启发式完善（`\documentclass` 优先、被 `\input` 引用）、多文件打开恢复
- ✅ 验收：外部改动提示重载；config 缺失时主文件识别仍正确

### M0-9 多遍编译（1–2 天）

- `compile_project()`：首选 `latexmk -xelatex -synctex=1`，兜底手写 `xelatex → biber → xelatex ×2`；tokio spawn + `compile_progress` / `compile_finished` 事件推送
- `cancel_compile()`；编译按钮接通；Windows `CREATE_NO_WINDOW`
- ✅ 验收：含 `\ref` 的文档编译两遍 `status=ok`、PDF 产出、取消生效

### M0-10 日志解析（1 天）

- `parse_tex_log()`：regex 提取 `{file, line, message}` → `TexError[]`，高频错误规则表映射大白话 `readable` + `fix`；接入 `compile_finished`
- ✅ 验收：3 份真实 .log 样本单测全绿；编译报错文档 errors 非空

### M0-11 错误定位（1 天）

- 错误列表面板（raw/readable/fix 分层）→ 点击条目 `gotoLine` 跳行 + 高亮
- ✅ 验收：真实缺 `$` 文档编译 → 点击报错跳到出错行 + 可读解释

> M0-9/10/11 详细实施计划见 `docs/开发/M0-3编译引擎.md`（原 3b/3c/3d）。
