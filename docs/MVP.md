# Zetla MVP 开发计划
## 一、基础信息
### 1. 项目定位
**MVP核心目标**：完成「打开项目→新建TeX文档→编写代码→一键XeLaTeX编译→查看PDF预览」完整闭环；只保留核心链路，砍掉所有非必要功能，保证第一版可自测可用。
### 2. 核心约束（MVP范围边界）
✅ 必须实现：项目树、多标签编辑器、一键编译+日志报错跳转、PDF预览、三栏布局、基础IPC文件读写与进程管理
❌ 全部后置：自定义模板导入、Synctex双向跳转、暗色主题、图片管理、绘图、全局设置、自动更新、打包清理

---

## 二、分阶段任务清单（前后端拆分+验收标准+时间预估）
### Phase 0：基础骨架 + 类型安全IPC（3天，前置依赖）
#### 0-1 目录结构与类型定义（半天）
1. 目录搭建（严格分层）
```
src/
├── types/          # TS类型，与Rust一一对应（核心协议）
├── ipc/            # 封装invoke+listen，类型安全调用
├── store/          # Zustand全局状态（项目、编辑器、编译状态）
├── components/     # 布局、文件树、编辑器、日志面板、PDF预览
├── modules/        # 编辑器模块、预览模块、项目模块
src-tauri/src/
├── commands/       # IPC命令（fs、compile、template三类）
├── models/         # Rust结构体，serde序列化，与TS对齐
├── fsdoc/          # 文件读写、目录扫描逻辑
├── compile/        # 子进程、latexmk调用、日志解析
├── template/       # 内置模板渲染
```
2. 统一数据模型（TS+Rust双向同步，改一处必改另一处）
- FileItem：文件/文件夹信息，路径、文件名、后缀
- CompileRequest：项目根目录、主文件路径
- CompileProgress：编译阶段、实时日志行
- TexError：文件路径、行号、原始报错、可读提示
- CompileResult：编译状态、PDF路径、错误数组、耗时
3. 配置Tauri capabilities文件系统权限，开启文件读写权限。

✅ 验收：TS与Rust类型完全匹配，编译器无类型不一致报错。

#### 0-2 IPC封装 + 文件基础命令（1天）
**Rust后端实现命令：**
1. 目录扫描：scan_dir(path) → 返回文件树列表（只识别tex/pdf/图片/文本文件）
2. 文件读取：read_file(path)，自动兼容GBK/UTF-8编码，不乱码
3. 文件写入：write_file(path, content)，原子写入（临时文件rename，防止文件损坏）
4. 文件操作：新建tex文件、新建文件夹、删除、重命名

**前端封装：**
1. src/ipc 封装带类型的invoke函数，杜绝any类型
2. 前端调用测试：选择文件夹→读取目录→读写tex文件

✅ 验收：前端调用Rust命令，目录读取、文件读写正常；GBK编码tex打开不乱码。

#### 0-3 窗口基础配置（半天）
1. 窗口大小记忆、最小化/最大化
2. 顶部菜单栏：文件、编辑、构建、视图、关于（仅占位，只实现菜单项点击事件）
3. 三栏布局容器（左文件树｜中编辑器｜右PDF预览）+底部日志面板；面板支持显示/隐藏

✅ 验收：布局可自由收起左右侧栏、底部日志栏；窗口尺寸重启自动记忆。

#### 0-4 持久化：记住上次打开项目（半天）
Rust简单读写本地JSON配置文件，仅保存上次打开的项目根路径；软件启动自动加载项目目录。

✅ 验收：重启软件自动打开上次项目文件夹。

### Phase 1：前端业务层（文件树 + CodeMirror编辑器 + 多标签Tab，4天）
#### 1-1 左侧项目文件树（1天）
1. 渲染目录树，区分文件夹、tex、pdf、图片、其他文件
2. 右键菜单：新建.tex、新建文件夹、删除、重命名
3. 点击文件，在中间打开对应标签页

✅ 验收：文件树操作全部可用；点击文件正常触发打开事件。

#### 1-2 CodeMirror6 编辑器核心（1.5天）
1. 集成 `@uiw/react-codemirror + codemirror-lang-latex`，开启LaTeX语法高亮、行号
2. 基础编辑能力：撤销/重做、查找替换
3. 打开文件：读取文件内容加载到编辑器；Ctrl+S保存文件

【暂不做】代码折叠、小地图、格式化

✅ 验收：tex文件高亮正常；保存后内容写入磁盘无乱码。

#### 1-3 多标签Tab管理 + 文件脏标记（1天）
1. 每个Tab独立EditorState，撤销栈互不干扰
2. 文件修改后Tab名称带`*`脏标记；关闭未保存文件弹出确认提示
3. 标签切换、关闭逻辑

✅ 验收：多文件切换无状态串扰；未保存关闭有拦截提示。

#### 1-4 自动保存（0.5天）
简单定时自动保存（30秒轮询检测脏文件，自动写入磁盘），无需复杂配置。

✅ 验收：修改文件等待30秒，内容自动落盘。

> 里程碑：**编辑壳完整可用，可以打开、编辑、保存多个TeX文件**。

---

### Phase 2：编译核心（Rust后端+日志解析+错误跳转，4天，MVP重中之重）
#### 2-1 编译子进程管线（1.5天）
1. 固定调用命令：`latexmk -xelatex -synctex=1 主文件.tex`；兜底手写xelatex多轮编译管线
2. Rust用tokio异步spawn子进程；Windows强制加`CREATE_NO_WINDOW`，不弹出黑控制台窗口
3. 全局单编译锁：同一时间只允许一次编译；实现`cancel_compile`终止子进程，避免进程残留
4. 逐行流式读取stdout/stderr，向前端推送`compile_progress`实时日志事件

✅ 验收：正常文档自动多轮编译成功生成PDF；编译中途可以一键终止；无残留后台进程。

#### 2-2 底部日志面板（0.5天，前端）
1. 实时滚动展示编译完整日志
2. 编译按钮绑定事件，触发后端编译命令；编译期间按钮置灰、显示取消按钮

✅ 验收：编译日志实时输出，滚动到底部。

#### 2-3 日志解析：提取报错信息（1天，Rust）
1. 读取.log日志文件，正则匹配`文件名:行号`报错位置
2. 内置基础错误规则（缺$、缺少\end、命令未定义、宏包缺失、引用未定义等），把原始英文报错转为中文可读提示+修复建议
3. 输出结构化`TexError`数组，通过`compile_finished`事件推送到前端

✅ 验收：3类真实报错日志单测全部命中，正确提取文件+行号+可读提示。

#### 2-4 错误列表 + 点击跳转编辑器（1天，前后端联调）
1. 前端渲染错误列表：展示文件名、行号、原始报错、中文修复建议
2. 点击报错条目，调用编辑器`gotoLine`接口，自动跳转到对应行并高亮

✅ 验收：编写带语法错误的TeX文档，编译后点击报错，光标精准跳转到出错代码行。

> 里程碑：**编译链路闭环：一键编译→看日志→点击报错定位源码**。

---

### Phase 3：PDF预览 + 内置模板 + 整体联调收尾（3天）
#### 3-1 PDF预览面板（1.5天，前端）
1. 集成pdfjs-dist，配置Vite worker，开启本地文件资源访问权限
2. 编译成功后自动加载生成的PDF文件
3. 基础操作：翻页、放大缩小、手动刷新PDF
4. 优化：重新编译后，保留当前页码、缩放比例，不自动跳回首页

【暂不做】Synctex双向跳转

✅ 验收：编译成功自动加载PDF；缩放翻页正常；重编译不丢失浏览位置。

#### 3-2 内置模板新建文档（1天）
1. Rust内置2个基础模板：`article`（单文件英文文档）、`ctex-cn`（中文LaTeX文档），无需自定义模板导入
2. 前端向导：新建文档→选择模板→自动生成main.tex并打开到编辑器
3. 自动把新建文件标记为项目主编译文件

✅ 验收：选择模板一键生成完整可编译的tex文档。

#### 3-3 全链路冒烟测试+Bug修复（0.5天）
严格按照MVP业务流程全流程走通：
打开软件→打开项目文件夹→从模板新建main.tex→编写代码→一键编译→查看日志→报错点击跳转→修正代码重新编译→预览PDF；切换文件、保存、关闭标签全部验证。

✅ 验收：完整业务流程无阻断，无内存/进程残留问题。
