# Zetla 拼图功能实现方案

> 依据原始设计稿（拼图功能模块总结）+ 代码核验整理。核心定位不变：**画布只是排布决策辅助，真正产物是 `subfigure` 代码**。

## 0. 相对原始设计稿的修正（先读这节）

1. **`subcaption` 宏包检测是净新增能力，不是复用。** 核验 `src/modules/table/` 后确认：表格模块只会*输出* `booktabs` 规则，**不存在**“检测缺失宏包 + 加入导言区提示”的 helper。拼图模块将*新建*这个共享能力，并可反哺表格模块。
2. **图片去重不是 `base-N`，而是 `slugify(文件名)` + Rust `import_image` 落盘。** 复用对象是 `src/editor/image/importImage.ts` 整条管线，而非假设的“base-1.ext 去重”。
3. **第一阶段大概率无需新增 Rust 命令。** 图片落盘复用现有 `import_image`，编译自检/预览复用现有 `compile` 命令。无需 `commands/figure.rs` 三处注册，除非后续新增专属 IPC。
4. **把“整行宽度预算校验”提升为阶段一核心算法。** 它决定生成的 `subfigure` 能否一次编译通过，比间距滑块重要得多。

## 1. 架构与数据模型

新增前端模块，镜像现有 `src/modules/table/`：

```
src/modules/figure/
  figureModule.ts      // 模块注册（参考 tableModule.ts）
  figureModel.ts       // FigureLayout 类型 + 默认值
  figureStore.ts       // zustand 状态（参考 modules/formula/composeStore.ts）
  FigureCanvas.tsx     // 画布 UI（网格 + 每格控件 + 间距滑块）
  figureGen.ts         // subfigure 代码生成（纯函数，复用 buildFigure）
  figureParse.ts       // 阶段二：parseSubfigure(code) -> FigureLayout（预留）
```

`FigureLayout`（建议放 `src/types/figure.ts`，与 Rust 一一对应仅在需要 IPC 时再补）：

```ts
interface FigureCell {
  path: string;          // 相对 .tex 路径（slugify 命名，复用 relativePath）
  scale: number;         // 统一模式外的微调系数（见 §3.4 优先级）
  crop: { l:number; b:number; r:number; t:number }; // 归一化 0–1 四边 trim
  align: 't' | 'c' | 'b';// 垂直对齐 -> subfigure [t]/[c]/[b]
  subCaption: string;    // 子标题（可含 $...$，KaTeX 预览）
  label: string;         // 自动生成 fig:sub-<letter>
}
interface FigureLayout {
  cells: FigureCell[];
  rows: number; cols: number;
  gapCol: number; gapRow: number;   // 内部以“占列宽比例”建模（见 §3.3）
  uniform: 'height' | 'width' | 'none';
}
```

`cells.length === 1` 即单图：数据层共用，交互层分离（单图走原 `importImage` 直插，不进画布）。

## 3. 必须先行定义的核心算法（阶段一）

### 3.1 网格填充与编号规则
- **行优先**填充；编号 `(a)(b)(c)…` 按填充顺序，写死行优先。
- 图片数 < 行×列：末尾空位**留空**（不生成 subfigure）。
- 图片数 > 行×列：**自动加行**（而非禁止），保持用户拖入即所见。
- 阶段一**不做跨格**（colspan/rowspan），写进边界。

### 3.2 整行宽度预算（保证编译通过）
- 统一宽度模式：每格 `width = w_i`（用户设定或按比例）。
- 统一高度模式：固定 `height = H`，`width_i = H * aspect_i`。
- **预算约束**：`Σ width_i + (cols-1) * gapCol ≤ 1.0\textwidth`。
- 超限：**等比缩放所有格 width** 至满足；优先用 `\hfill` 均分剩余空间，避免硬比例溢出换行。
- 生成口径：`\begin{subfigure}[t]{0.xx\textwidth}` + 内部 `\includegraphics[width=\linewidth]` 吃满。

### 3.3 间距映射（绕开“像素→比例”糊涂账）
- 内部以“占列宽比例” `gapCol, gapRow ∈ [0,1]` 建模，画布按比例渲染，**不暴露像素**。
- 列间距 → `\hfill`（均分）或固定 `\hspace{gapCol\textwidth}`；行间距 → `\vspace{gapRow\textwidth}` 或 `\medskip`。
- 给出具体公式后才写 UI，否则间距代码与滑块对不上。

### 3.4 裁剪与对齐的优先级
- `crop` 统一为**归一化 0–1**；LaTeX 侧 `trim= L B R T, clip`，PNG 侧 Canvas 裁，三路径语义一致。
- `scale` 与 `uniform` 叠加规则二选一：要么统一模式定基准、`scale` 再乘；要么统一模式下禁用 per-cell `scale`。**必须选一条**。
- `align` 明确为**垂直对齐**（影响同行基线）→ subfigure `[t]/[c]/[b]`；阶段一可先固定 `[t]`。

## 4. 分阶段切片

### 阶段一（覆盖 ~90% 需求，复用最多）
- **F1** ✅ `FigureLayout` 类型 + zustand store（已完成：`src/types/figure.ts` + `src/modules/figure/figureStore.ts`，`npm run build` 通过）。
- **F2** 网格布局 UI：行列输入 + 行优先自动填充 + 编号实时预览。
- **F3** 每格控件：缩放 / 裁剪 / 对齐 / 子标题输入 + KaTeX 预览。
- **F4** 全局行/列间距滑块（内部比例建模）。
- **F5** `subfigure` 代码生成：外层调 `buildFigure`，内部宽度预算 + 间距映射（§3.2/§3.3）。
- **F6** 多图导入分支：`importImage.ts` 检测多图 → 路由到画布预填。
- **F7** 单图直插保留：不动现有 `importImage` 逻辑。
- **F8** `subcaption` 检测 + “加入导言区”提示 helper（**净新增，抽成共享**）。
- **F9** 生成后**编译自检 / 一键预览**（复用 `compile`），失败高亮超宽行。
- **验收**：给定不同比例 N 张图 + 指定行列，生成代码一次编译通过；风格与 `buildFigure` 一致。

### 阶段二
- **F10** PNG 合成导出（前端 Canvas，零后端依赖）。
- **F11** PDF 合成导出（复用 `compile`，`standalone` 按坐标摆放——**成本需先评估**，建议阶段二先只做 PNG）。
- **F12** 单图“进画布微调”入口（右键）。
- **F13** 反向编辑回填：`parseSubfigure(code) -> FigureLayout`（§1 已预留 `figureParse.ts`）。

### 阶段三
- **F14** 自由拖拽布局。
- **F15** TikZ 代码导出（单向，非主路径）。
- **F16** 公式子标题 LaTeX 编译保真导出。

## 5. 风险与开放问题

- **单图直插现有链路**需先确认 `importImage.ts` 对“一次拖入多张”的行为；多图分支是新增，单图逻辑保持零改动。
- **PDF standalone 合成**坐标计算复杂度高于直觉，依赖现有编译管线；建议阶段二先交付 PNG，PDF 后置。
- **跨 IPC**：阶段一无需新 Rust 命令；若阶段二 PDF 合成需新参数，复用 `compile` 而非新建命令。

## 6. 阶段一验收标准

1. 不同比例 N 张图 + 指定行列 → 生成的 `subfigure` 代码**一次 `compile` 通过**。
2. 间距 / 裁剪 / 子标题在画布中**相对关系正确**（画布是近似 WYSIWYG，非像素保真）。
3. 单图拖入仍**零步骤直插**，行为与现状一致。
4. 缺失 `subcaption` 时给出“加入导言区”提示，且提示逻辑可被表格模块复用。
