## 0. 相对原始设计稿的四条修正（已代码核验）

1. **`subcaption` 宏包检测是净新增，不是复用。** 表格模块只会*输出* `booktabs` 规则，不存在“检测缺失宏包 + 加入导言区”的 helper。拼图将*新建*这个共享能力，并可反哺表格。
2. **图片去重不是 `base-N`，而是 `slugify(文件名)` + Rust `import_image` 落盘。** 复用对象是 `src/editor/image/importImage.ts` 整条管线。
3. **阶段一无需新增 Rust 命令。** 落盘复用 `import_image`，编译自检复用 `compile`。
4. **整行宽度预算是生死线**，必须提升为阶段一核心算法（保证生成代码一次编译通过）。

## 1. 预期功能（产品定义 / v2 目标形态）

### 1.1 核心定位
不是从零画图，而是把多张图片可视化拼成论文插图。提供**两种平级模式**：`subfigure` 模式与**合成单张图片**模式——二者只是**实现先后顺序不同**（先 `subfigure`、后合成单张图片），并非主从关系。TikZ 代码导出为进阶选项，不追求反向解析。

### 1.2 入口与路由
- **多图**选中 / 拖入 / 粘贴 / 菜单 → 自动进入拼图工作流：侧栏控制面板 + **自动打开预览 Tab** 并预填。
- **单图**拖入 / 粘贴 → 仍走原逻辑**零步骤直插**单图 `figure`，不进画布；右键「在画布中编辑」为阶段二进阶入口。

### 1.3 侧栏控制面板（纯控制，不渲染画布）
纵向单列，自上而下：
1. **模式开关**：`subfigure` | 合成单张图片（segmented control）。决定 Tab 页的渲染模式（§1.4）与底部主操作（§1.5），两模式平级。
2. 行列输入（行 / 列 number，clamp）。
3. 导入 / 清空 + 「打开预览」按钮。
4. **`CellList`**：行优先子图列表，编号徽标 + 文件名 + 状态点；空槽不可选；选中行左侧蓝色竖条（替代原「点格选中」交互）。
5. **设置区 `figside-edit`**（一个分组，仅在已导入图片时出现）——组内卡片统一用 `figside-card` 外观，内容随选中态整体切换：
   - **未选中任何子图**：两张卡并列组内 —— ① **`GapControls`**（行 / 列间距滑块）；② **`CaptionField`**（图片标题）。
   - **选中某子图**：只显示该子图的 **`CellEditor`** 卡（子标题 + KaTeX 预览 / 缩放 / 对齐分段 / crop 2×2）。
6. **图片标题**（`CaptionField`，整图属性，属于设置区）：单行文本输入 → 写 `layout.caption`。它就是**总图的 `\caption{}`**，生成代码时自动写上（subfigure 与合成两种模式都用）；**合成模式下同时用作合成 PNG 的文件命名**——填了则以它为文件名（`<标题>.png`），未填则默认 `fig-<slug>-composite.png`（`<slug>` 取首个来源图 slug）；同名文件**直接覆盖**，不弹冲突框。
7. 底部 **sticky 主操作按钮**：动作随当前模式变化——`subfigure` 模式 → 「生成 subfigure 代码」；合成单张图片模式 → 「合成单图并插入」（首次轻确认，提示合成会把子标题烘焙进图片——编号与文本转为像素、不再作为可独立编辑的 LaTeX `\subcaption`）。

### 1.4 中心 Tab 画布（单例 `figure://preview` 伪 buffer）
- **渲染模式由侧栏「模式开关」决定，不单独提供自由切换**：`subfigure` 模式 → 近似预览；合成单张图片模式 → 合成预览。
- **近似预览**（`FigureApproxPreview`，DOM）：绑定 `subfigure` 模式。即时、免编译，反映排版决策（行列 / 宽比 / 间距 / 裁剪 / 对齐 / 编号）。精度评估：决策层 ≥95%，像素保真层 70–85%（随模板字体 / 版心 / caption 样式漂移）；最大不可消除误差是 `\textwidth` 真实宽度未知。
- **合成预览**（`FigureRealPreview`，Canvas）：绑定合成单张图片模式。调用 `figureCompose` 实时合成，所见即产物，零漂移。版心宽度与近似预览一致（`min(720px, 100%)`），**长图按自然高度展示、超出视口纵向滚动**（纸张不参与 flex 收缩，避免被压扁裁切）。
- 侧栏切换模式时，Tab 即时切换为对应渲染；首次多图导入自动打开 / 聚焦该 Tab。

### 1.5 两种导出模式（与预览强绑定，平级）
两种模式**平级**，仅实现先后顺序不同（先 `subfigure`、后合成单张图片）：
- **`subfigure` 模式 · 生成 `subfigure` 代码**：外层调 `buildFigure`，内部按宽度预算 + 间距映射生成；图片保持独立文件，后期改单张不用重拼。生成时**后台跑一次 `compile` 自检**，失败才提示 + 高亮超宽行（不阻塞插入，保持流畅）。对应 Tab 仅显示**近似预览**。
- **合成单张图片模式 · 合成单图并插入**：调用 `figureCompose` 预览即产物，导出 `toBlob` → 落盘（复用 `importImage` 的 `slugify` + `relativePath`）→ 单图直插（外层 `buildFigure`，`\includegraphics` + `\caption{图片标题}`）。**落盘命名**：图片标题填了 → `<标题>.png`（就用它当文件名）；未填 → `fig-<slug>-composite.png`；同名文件**直接覆盖**。对应 Tab 仅显示**合成预览**。
- 绑定逻辑：模式决定 Tab 渲染（§1.4）；`subfigure` 的排版变量（`\textwidth` / 字体 / caption 样式）由用户模板决定 → 只能近似；合成单张图片把变量内化进位图 → 天然精确（但插回 LaTeX 后仍受 `\includegraphics[width=...]` 缩放影响，绝对像素不保真、相对布局保真）。合成会把**子标题（(a) + 文本）烘焙进图片**——编号与文本转为像素、不再作为可独立编辑的 LaTeX `\subcaption`，这是该模式的固有代价，不削弱其作为平级模式之一的定位。

### 1.6 数据模型（一句话）
`FigureLayout` = 网格参数（行列 / 间距 / 统一模式）+ `cells[]` + `mode`（subfigure / composite 平级模式）；`cells.length === 1` 即单图，数据层共用、交互层分离。v2 新增 `naturalSize`(aspect)、`selectedIndex` 与 `mode`（进 store，驱动 Tab 渲染与导出动作）。

### 1.7 边界
- 复杂度限定在「论文示意图 / 流程图」级；跨格（colspan）、自由拖拽、TikZ、反向编辑回填留阶段二 / 三。
- MVP 仅亮色主题（`data-theme="light"`）。

## 3. 数据模型（含 v2 补全）

```ts
type FigureCellSource =
  | { kind: 'path'; abs: string }     // 菜单选图 / 拖入的原始磁盘路径（预览零拷贝）
  | { kind: 'file'; file: File };     // 拖入 / 粘贴的 File（无稳定路径，内存预览）
interface FigureCell {
  source?: FigureCellSource;          // 原始来源（选图即记录，生成时才落盘，避免污染项目）
  path: string;                       // 相对 .tex 路径；仅生成代码时由落盘结果回填（此前为空）
  scale: number;                      // 统一模式外的微调系数（基准 × scale）
  crop: { l:number; b:number; r:number; t:number }; // 归一化 0–1，canonical 原点见 §4.3
  align: 't' | 'c' | 'b';             // 垂直对齐 → subfigure [t]/[c]/[b]
  subCaption: string;                 // 可含 $...$ / $$...$$（KaTeX 预览）
  label: string;                      // 自动生成 fig:sub-<letter>
  naturalSize?: { w:number; h:number }; // v2 新增：预览时从 <img> 读取，算 aspect
}
interface FigureLayout {
  cells: FigureCell[];
  rows: number; cols: number;
  gapCol: number; gapRow: number;     // 内部以“占列宽比例”建模 [0,1]
  uniform: 'height' | 'width' | 'none';
  mode: 'subfigure' | 'composite';    // 侧栏模式开关：决定 Tab 渲染与导出动作（两模式平级）
  selectedIndex: number;              // v2 新增：当前选中子图（-1 未选）
  caption: string;                    // v2 新增：图片标题 → 总图 \caption{}；合成 PNG 命名来源（§1.3）
  label: string;                      // 总图 \label{}（合成模式沿用或留空）
}
```

- **延迟落盘（关键约定）**：选图 ≠ 落盘。选图只把 `source`（原始路径或内存 File）写进 store，预览直接用原始路径 / 对象 URL（零项目污染）；**只有点「生成 subfigure 代码」时**才把真正进入代码的图片经 `import_image(_from_path)` 拷入 `figure/`（去重命名），并回填 `cell.path`。因此 `figure/` 只保留项目实际引用的图，实验性选图不再留垃圾文件。
- **格式支持**：`EXT_IMG`（含 `pdf`）覆盖选图 / 拖放 / 粘贴 / 插入菜单；PDF 在预览中以占位卡显示（`<img>` 无法渲染），但生成代码 `\includegraphics{figure/x.pdf}` 由 LaTeX 原生支持。

- `cells.length === 1` 即单图：数据层共用，交互层分离。
- **模式 (`mode`) 进 store**：侧栏「模式开关」写入，Tab 据此渲染（subfigure → 近似预览；composite → 合成预览），不另设独立的预览类型开关（预览与模式一一绑定，见 §1.4 / §1.5）。

## 4. 核心算法（必须先行定义，不可留待实现）

### 4.1 网格填充与编号规则
- **行优先**填充；编号 `(a)(b)(c)…` 按填充顺序，写死行优先（bijective base-26，a…z、aa 进位）。
- 图片数 < 行×列：末尾空位**留空**（不生成 subfigure、不占编号）。
- 图片数 > 行×列：**自动加行**（而非禁止），保持拖入即所见。
- 阶段一**不做跨格**（colspan / rowspan），写进边界。

### 4.2 整行宽度预算（A 路径，保证编译通过）
- 统一宽度模式：每格 `width = w_i`（用户设定或按比例）。
- 统一高度模式：固定 `height = H`，`width_i = H × aspect_i`（**依赖 §3 `naturalSize`**）。
- **预算约束**：`Σ width_i + (cols-1) × gapCol ≤ 1.0\textwidth`。
- 超限：**等比缩放所有格 width** 至满足；优先用 `\hfill` 均分剩余空间，避免硬比例溢出换行。
- 生成口径：`\begin{subfigure}[t]{0.xx\textwidth}` + 内部 `\includegraphics[width=\linewidth]` 吃满。

### 4.3 裁剪与对齐（钉死原点，三路径一致）
- **canonical 原点定义**：`crop` 以**图片左上角为 (0,0)，x 向右、y 向下**（与 Canvas `drawImage` 源矩形一致）。LaTeX `trim=L B R T`（bottom-up）由该归一化 crop **换算**：
  `L = l·W`、`R = r·W`、`B = b·H`、`T = t·H`；DOM 近似用同一 crop 做 CSS clip / `object-fit`。**三路径同源、无上下颠倒**。
- `scale` 优先级（F3 已落地）：统一模式定基准尺寸，`cell.scale` 再乘为微调系数，不与 `uniform` 互斥。
- `align`：明确为**垂直对齐**，且为**行级属性**（LaTeX 同行子图共享一条基线，混用 [t]/[b] 会让 [b] 整体升到基线上方、[t] 垂到下方）→ 整行统一 subfigure `[t]/[c]/[b]`（store 的 setAlign 按整行写入）；Canvas 合成时同行不同高度格子的垂直落点公式须写死：顶（基线贴行顶）/ 中（垂直居中）/ 底（贴行底）。

### 4.4 间距映射（比例建模，不暴露像素）
- 内部以“占列宽比例” `gapCol, gapRow ∈ [0,1]` 建模，不暴露像素（侧栏滑块显示为其百分比）。
- **列间距 `gapCol`（行内水平间隔预算）**：同一行内相邻子图之间的间隔。算法在整行可用宽度中按 `(k-1) × gapCol`（`k`=该行参与子图数）预留空间，使每个子图按 §4.2 宽度预算等比变窄，剩余空间再由行内 `\hfill` 弹性均分——既不溢出换行，又体现“列与列之间留多少空”。**并非**固定像素或固定 `\hspace`。
- **行间距 `gapRow`（行间垂直间隔）**：相邻两行之间直接渲染为 `\vspace{gapRow\textwidth}`（gapRow 个 `\textwidth` 的竖直空白），控制“行与行之间留多少空”。
- 合成单张图片模式（Canvas）：由 `figureCompose` 内部换算 `colGapPx = gapCol × targetWidthPx × (归一化参与列)`，同理行；**不**套用 LaTeX 溢出约束（见 §4.5）。

### 4.5 合成预算（合成单张图片模式，`figureCompose`）
- 输入：`layout`、预加载 `Map<index, CanvasImageSource>`（raster → `HTMLImageElement`；**PDF → 首页栅格化为 canvas**，复用 pdf.js，选页后置阶段二）、`targetWidthPx`（如 1600）。
- 按 §4.2 **相对比例算法 × `targetWidthPx`** 归一算格宽（注意：Canvas 无 `\textwidth` 溢出概念，是归一而非约束）；按 gap 算间距；按 §4.3 align 算基线；用 `ctx.drawImage` 源矩形 + §4.3 crop 裁剪采样。
- **子标题烘焙**（始终开启，与 subfigure 图下标注一致）：每格在子图下方居中渲染 `(a)`+文本——`(a)` 取 `subFigureLetter(index)`（行优先，含 P3-2 重排后重算），首行编号**粗体**、文本常规；字号随总宽等比例（≈ 2.4% `\textwidth`）含兜底，中文逐字断行、Latin 词整体不断（超宽下挪）。**`$...$` / `$$...$$` 公式**经 MathJax 渲染为**自包含 SVG**（字形为 `<path>`，`fontCache:'local'`）后画入 canvas——不污染画布，故导出 PNG 同样带公式；公式渲染失败则回退为纯文本（去 `$` 保留原文）。
- 行级对齐作用于「图片+子标题」单元块整体，子标题（含公式图片）高度计入行高，多行子标题不会压到下一行图。
- 返回 `HTMLCanvasElement`；预览 `toDataURL()` 与导出 `toBlob()` **共用同一函数 → 零漂移**。

## 9. 风险与开放问题

- **Tab 设施跨分支（T0 前置）**：v2 依赖的「伪路径 buffer + 中心画布」范式在 `feature/diagram`，`feature/figure-collage` 尚未包含，需 port 或待 diagram 合入 main 后 rebase；**切勿用 `tabMode`**（会误开绘图画布）。
- **`naturalSize` 来源**：导入时落盘记录 vs 预览时从 `<img>` 读 `naturalWidth/Height`，二者择一，影响 §4.2 统一高度预算与近似预览精度。
- **crop 原点已钉死**（§4.3 canonical 左上角），消除 DOM/Canvas/LaTeX 三路径上下颠倒风险。
- **暗色主题**：实测界面出现过暗色，而 MVP 仅亮色（`data-theme="light"`）；非功能阻塞，单独排查。
- **两模式平级、仅实现顺序不同**：`subfigure` 先实现、合成单张图片后实现，二者非主从关系；合成会把子标题（(a) + 文本）烘焙进图片是该模式的固有代价（编号/文本转为像素，不再作为可独立编辑的 LaTeX `\subcaption`），不影响其作为平级模式之一的定位。
