## 1. 架构总览

```
                 ┌──────────────────────────────────────────┐
                 │  .zfig (Model · 唯一真源, JSON schema v1)  │
                 └──────────────────────────────────────────┘
                    │  read ◀──┐            ┌──▶ write
        ┌───────────┴────┐     │            │
        ▼                ▼     ▼            ▼
   fabric 画布       LaTeX 序列化器      SVG/PDF/TikZ
   (实时预览/编辑)      (B 渲染中间产物)    序列化器
        │                │                 │
        │                ▼                 │
        │         Rust compile_standalone  │
        │         (复用 compile.rs 引擎)    │
        │                │                 │
        │                ▼                 ▼
        │          <id>.pdf (B)      <id>.{svg,png,eps,tiff} (C)
        │                │                 │
        └────────────────┴─────────────────┘
                         ▼
            文档插入：% @zfig <id> <hash> + \includegraphics{<rel>.pdf}
```

**分层原则（对应 PRD §3.1 唯一真源 / §3.3 渲染可插拔）**：

1. **`.zfig` 是 model**，fabric 画布、LaTeX、SVG、PDF、TikZ 都是它的 **view / serializer**。换 fabric 版本、加新导出格式，只动对应 serializer，不动真源。
2. **TS 拥有模型与序列化**（fabric 在 JS 侧，图元几何、样式、文本转义都在 TS 算）；**Rust 拥有文件 IO 与引擎/工具调用**（复用 `compile.rs`、新增 sidecar）。二者经 `invoke` 边界通信，类型走 `src/types/diagram.ts`（类型即协议）。

## 3. 数据模型 `.zfig`（schema v1，具体）

在 PRD §8 约束基础上给出可序列化结构。fabric 私有字段（`originX/originY/strokeUniform`）**不入库**，由 `canvas/` 适配器在读写时转换。

```jsonc
{
  "schemaVersion": 1,
  "id": "d_<uuid>",                       // 真源文件名与文档锚点共用
  "canvas": { "width": 0, "height": 0, "dpi": 600, "background": "#FFFFFF" },
  "elements": [
    {
      "id": "e_<uuid>",
      "type": "rect|ellipse|line|arrow|polyline|text|image|group",
      "x": 0, "y": 0, "w": 0, "h": 0, "rotation": 0,
      "style": { "stroke": "#000000", "strokeWidth": 0.5, "fill": "none",
                 "font": "sans|serif", "fontSize": 10, "align": "center" },
      "text": { "content": "v", "role": "label|caption|normal", "italic": false, "math": false },
      "src": "assets/fig1.png",            // 仅 image 类：相对项目根
      "points": [ [x,y], ... ],            // 仅 polyline/arrow
      "curve": "none|arc|parabola|sin|c1", // 预设曲线（PRD §3.2）
      "children": [ "<e_id>", ... ]        // 仅 group
    }
  ],
  "layout": { "subfigures": { "cols": 2, "rows": 2, "gap": 4, "labels": ["(a)","(b)"] } },
  "meta": { "created": 0, "modified": 0, "backend": "B|C" }
}
```

**持久化**：`<项目根>/.ltex/diagrams/<id>.zfig`，与 `.ltex/config.json` 同级、随项目迁移。加载时按 `schemaVersion` 校验，高版本低打只读并提示。单文件模式（`~/.zetla/diagrams/`）。

## 4. fabric ↔ `.zfig` 适配器（必做，非可选项）

PRD v0.4 可行性分析明确：`.zfig` 不能存 `canvas.toJSON()`（fabric 版本强耦合）。本层职责：

- **write（编辑 → 真源）**：监听 fabric 对象变更（增删改/变换），转换成上面的归一化 `elements` 写盘（防抖 300ms）。
- **read（真源 → 编辑）**：读 `.zfig` 重建 fabric 对象；`style.font` 映射 fabric `fontFamily`；`text.math=true` → 以 `$...$` 包裹进入画布文本。
- **锚点**：序列化 LaTeX 时每个图元前写 `% @el <e_id>`，供 B 编译报错反查（PRD §7.5）。

此层是"自研格式"成立的关键，D0 必须随画布基础编辑一起落地，不能等。

## 5. 渲染后端

### 5.1 B（默认 · LaTeX 编译渲染）

**流程**：TS `serializers/latex.ts` 把 `.zfig` 序列化为独立 `.tex` → 写 `<项目根>/.ltex/diagrams/<id>/<id>.tex` → Rust `compile_standalone(tex, engine, out_dir)` 复用 `compile.rs` 引擎检测 + `latexmk -xelatex -interaction=nonstopmode` → 产出 `<id>.pdf`（`standalone` 文档类自动裁 bbox，无需 pdfcrop）。

**序列化要点**：

- 样式集中在 `\tikzset{zbox/.style={...}, zarrow/.style={->}}`，与 PRD"可预测/可手改"原则一致。
- **文本转义（B 唯一新风险类别，必须做）**：`& % # $ \ { } ~ _ ^` 强制转义；`math:true` 内容用 `$...$` 包裹；`italic:true` 拉丁字母发 `$v$`。转义逻辑单测覆盖。
- **位图（拼图）**：`\node{\includegraphics[width=..]{<src>}}`，`src` 取相对 tex 的路径。
- **preamble 策略（D0 默认 → D2 精修）**：D0 用固定 preamble（`\usepackage{tikz,graphicx}` + ctex 基础）；D2 再扫描项目主文件 `\usepackage` 行以镜像文档字体（PRD §6.5）。中文在 B 下因走 xelatex+ctex **自动正确**。
- **TikZ 导出**：B 的中间产物即 `tikzpicture`，导出时直接交还用户（仅自由笔迹类 image 跳过，标注"未完整转换"）。

**失败定位**：B 编译报错时按行号找最近 `% @el <e_id>` 映射回图元，提示"图元 X 的标签含非法字符"，不暴露裸 LaTeX 报错（PRD §7.5）。

### 5.2 C（EPS/TIFF · 随包原生转换器）

**流程**：TS `serializers/svg.ts` 取 `canvas.toSVG()` → 写 `<id>.svg` → Rust `convert_raster(svg, format, dpi)` 调 **sidecar**：

- **resvg**（Rust 原生、极小、无依赖）出 PDF/SVG，作 C 主路径与 A/D 缺位时的兜底。
- **Ghostscript**（sidecar，win/linux/mac 三平台打包）出 EPS/PS/TIFF——**唯一干净覆盖 EPS/TIFF 的路径**（PRD §6.3.1）。

**代价**：Tauri sidecar 形式带二进制；优先 resvg（小），Ghostscript 仅按需（EPS/TIFF 触发）评估体积取舍。中文依赖系统/内置 CJK 字体，C 路径列为"字体近似"已知限制（PRD §7.3）。

### 5.3 可插拔与 fast path

`renderDiagram(req)` 按 `req.backend` 派发 B/C；A（纯 JS）/D（Chromium 打印）留作"无 TeX 环境 / 批量即时"的后续 fast path，接口预留不实现。文档侧只引用产物，不感知后端（PRD §3.1）。

## 6. 文档集成与冲突

- **插入**：`insert.ts` 在光标处写 `% @zfig <id> <hash>` + `\includegraphics[width=\linewidth]{<rel>.pdf}`，`<rel>` = 由主文件位置算到 `.ltex/diagrams/<id>.pdf` 的相对路径（TS 计算，避免硬编码绝对路径）。
- **重渲染**：改 `.zfig` → 重渲染同名 PDF（默认 B）→ 文档引用不变，下次编译即更新。
- **冲突检测（PRD §7.4）**：`<hash>` = `.zfig` 内容摘要。再次打开画布时比对真源 hash 与文档锚点 hash：一致→正常；真源被外部改→提示"真源已变，按最新重渲染"；文档锚点缺失→生成新 id，**禁止静默覆盖、禁止重复追加**。
- **内联 TikZ 可选模式**：用户勾选时把 B 的 `tikzpicture` 内联替代 `\includegraphics`（D3 打磨保真度）。

## 7. 撤销 / 重做

- 自研栈 `canvas/history.ts`：每次"可撤销操作"（新增/删除/变换/样式改/文本改）压栈，`Ctrl+Z`/`Ctrl+Shift+Z`，**≥ 50 步**，重做后状态逐像素一致（PRD §6.1 验收门槛）。fabric 自带 `History` 插件可评估复用，但需确认其栈深与逐像素一致性，不满足则自研。
- 撤销栈与 `.zfig` 写入解耦：撤销只回滚画布状态，落盘走防抖。

## 10. 预研 spike（B+C 渲染验证 · 1–2 天，D0-5 前完成）

PRD 可行性讨论遗留的选型不确定，用最小验证消掉：

1. 取一张**含中文标注 + 箭头 + 圆角框**的样例图，分别用 **B（latex.ts→xelatex）** 与 **C（resvg/Ghostscript）** 各出一版 PDF/EPS。
2. 对比维度：中文保真度、文件体积、生成耗时、代码量、EPS 是否被主流投稿系统识别。
3. 顺带验证：resvg 对中文的嵌入可行性、Ghostscript sidecar 三平台打包体积。
4. 结论回写 §5，决定 resvg/gs 取舍与是否需内置 CJK 字体。

> 若 spike 显示 C 在中文/体积上不可接受，则 D1 的 EPS/TIFF 降级为"按需外调 Ghostscript"，不影响 D0 主线。

## 12. 风险（PRD §13 的工程化补充）

- **新增 sidecar 三平台打包**（C）：Ghostscript 体积大，优先 resvg；D1 才动，不阻塞 D0。
- **`compile_standalone` 与项目编译抢引擎/PATH**：复用 `compile.rs` 的 PATH 前置注入逻辑，独立临时目录，避免污染项目 `build/`。
- **fabric 版本升级破坏 `.zfig`**：靠 §4 适配器隔离；`schemaVersion` 兜底。
- **文本转义遗漏致 B 编译失败**：转义单测 + `% @el` 反查，PRD §7.5 已覆盖。
- **大画布/大位图内存**：D0 设图元 200、画布 4000×3000 上限，超限提示分块（非阻塞）。
