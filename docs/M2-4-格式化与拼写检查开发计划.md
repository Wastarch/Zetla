# M2-4 代码格式化 / 拼写检查 —— 开工方案（v0.2 · 2026-10-29）

> 本文是**方案稿**（暂不动代码）。v0.1 曾拟"自研格式化器 + 自研词表"，据用户 2026-10-29 反馈改为评估 **tex-fmt** 与 **LTeX+ / Spell Right** 两条成熟路线，结论写在 §2。
> 上游口径：`docs/开发计划.md` M2-4「基础格式化（缩进/空行规范）+ 拼写提示（可关闭）｜选中/全文档格式化；拼写错词波浪线」。

---

## 1. 目标与边界

### 1.1 做什么

| 能力 | 用户可见结果 |
|---|---|
| 格式化 · 全文 | 编辑菜单 / `Shift+Alt+F` → 当前文档按规则规范化，**整次操作一个撤销步** |
| 格式化 · 选区 | 有选区时只格式化选中区域（自动扩展到最近的环境边界，见 §3.1） |
| 格式化 · 逃生口 | 支持 `% tex-fmt: skip`（单行）/ `% tex-fmt: off/on`（区块）——沿用 tex-fmt 原生指令，零额外成本 |
| 拼写检查 · 波浪线 | 开启后英文错词下方 `info` 波浪线，悬停显示建议；行号槽可见 |
| 拼写检查 · 交互 | 右键：「替换为 xxx」「加入词典」「忽略一次」「全部忽略」 |
| 拼写检查 · 开关 | 设置 → 编辑器 →「拼写检查（英文）」默认 **关**，切换即时生效（CM6 Compartment） |

### 1.2 明确不做（本期）

- **不做中文错别字/语法检查**：Hunspell 无中文词典；LanguageTool 的 zh-CN 只有少量规则。中文语义纠错留给 M4 的 AI 能力（或 §2.2 的可选 LanguageTool 后端）。
- **不做正文重排**：默认 `wrap=false`，不合并/重排正文行（学术稿的行内换行是作者意图，重排会污染 diff）。
- **不打包 Java**：不随包分发 ltex-ls / LanguageTool（见 §2.2 结论）。
- **不在本期做格式化 diff 预览**：M2-4d 可选片。

## 2. 关键技术决策（含调研结论）

### 2.1 格式化引擎：**采用 tex-fmt（Rust crate 内嵌）** ✅

调研对象：[WGUNDERWOOD/tex-fmt](https://github.com/WGUNDERWOOD/tex-fmt)（crates.io `tex-fmt`，**MIT**，纯 Rust，v0.5.x）。

**事实核对**

| 维度 | 事实 |
|---|---|
| 能力 | 缩进、行包裹（wrap）、表格 & 对齐（可选）、`.tex/.bib/.cls/.sty` |
| 性能 | 官方基准：94k 行 / 3.5MB → **0.055s**；latexindent 同条件 106s（≈1900×） |
| 安全边界 | `verbatim / Verbatim / lstlisting / minted` 自动跳过；支持 `% tex-fmt: skip` 与 `% tex-fmt: off/on` |
| 配置 | `tex-fmt.toml` 或 `Args` 结构体：`wrap`(默认 true)、`wraplen`(80)、`wrapmin`(70)、`tabsize`(2)、`tabchar`(space)、`format-tables`(false)、`lists`、`verbatims`、`no-indent-envs`、`wrap-chars`(如 `["。"]`) |
| 可嵌入 | `tex_fmt::format::format_file(old_text: &str, file: &Path, args: &Args, logs: &mut Vec<Log>) -> String` —— **字符串进、字符串出**，`Args: Default` 可编程构造 |
| 已知坑 | 文档明示 **可能 panic**（不可恢复错误）；默认 `wrap=true` 会按 80 列重排长行 |

**为什么选它而不是 latexindent.pl**：latexindent 需 Perl（Windows 上要靠 TeX Live 自带 tlperl 或另装）、GBK 中文注释有编码风险、大文档秒级；tex-fmt 是同一生态里被 LaTeX Workshop / Neovim 广泛接入的现代替代品，且**是 Rust，能直接编进 Tauri 后端**，不需要外部进程。

**为什么选它而不是自研格式化器（v0.1 方案）**：自研要自己维护环境栈、缩进层级、verbatim 保护区、幂等性，测试面大且规则永远比不过社区；tex-fmt 的"只做缩进/空白、不做语义解析"恰好就是我们想要的保守语义。

**接入形态（两个选项，需拍板）**

| 形态 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 作为 crate 依赖（推荐）** | `src-tauri/Cargo.toml` 加 `tex-fmt = "0.5"`；新增命令 `format_latex`，构造 `Args` 调 `format_file`，`catch_unwind` 兜底 | 单一 exe、无外部进程、版本随 Cargo.lock 锁定、参数可控 | 依赖树变大（regex / rayon / clap / toml / ignore 等），首次 `cargo build` 变慢，发布包 +1~2MB |
| B. 预编译 exe 作 sidecar | 下载 tex-fmt release 的 `tex-fmt.exe`，`tauri.conf.json` 配 `externalBin`，`Command::new(sidecar).args(["--stdin","--nowrap"]).stdin(...)` | 后端零新依赖、编译快 | 多一个二进制要随包分发/签名；路径与权限问题；升级要手工换文件 |

**结论：A**（内嵌）；若后续发现构建时间或体积不可接受，再退 B，前端命令签名不变。

**落地前必须处理的 4 个细节**

1. **关掉 wrap**：`Args { wrap: false, ..Default::default() }`（否则中文段落被切行、diff 爆炸）。设置里给「长行包裹」独立开关，开启时 `wraplen=100` 且 `wrap_chars = ['。','，','、','；','：']`。
2. **panic 兜底**：`std::panic::catch_unwind(AssertUnwindSafe(...))`，失败返回 `Err("格式化失败，文档未改动")`，**绝不写盘**。
3. **EOL 保真**：入参先统一成 `\n`，格式化后按原文检测到的 EOL（`\r\n` 或 `\n`）还原；避免 Windows CRLF 文档被改写成 LF（会污染整个文件的 diff）。
4. **选区语义**：tex-fmt 没有"只格式化片段"的官方能力。策略：把选区按行边界扩展到「最近一个不跨界的完整环境块」；若选区横跨 `\begin`/`\end` 边界，则扩展到整块再格式化，并在 toast 里说明「已扩展到环境边界」。跨文件片段（`\begin` 在别的文件）无法处理时直接拒绝并提示。

**保留的原生能力**：`--check`（等价"是否已规范"）用 `format_file` 前后对比即可；`format-tables`（表格 & 对齐）作为设置开关，默认关（会动 `&` 对齐，属于"重排"）。

### 2.2 拼写检查：**采用 Rust `spellbook` + Hunspell 词典（= Spell Right 架构），LTeX+ 降级为可选外部后端**

**三家对比**

| 方案 | 本质 | 能力 | 体积/依赖 | 集成成本 | 对本项目的适配性 |
|---|---|---|---|---|---|
| **LTeX+（ltex-ls + LanguageTool）** | Java LSP 服务（JSON-RPC over stdio） | 拼写 + **语法 + 风格 + 标点**，LaTeX 感知解析，20+ 语言（含 zh-CN 少量规则） | 离线包含 JRE ≈ **150–300MB**；首检 30s~2min；高 CPU | 需自实现 LSP 客户端 + 文档同步 + diagnostics/CodeAction 映射，工作量远超本切片 | ❌ 不能直接"搬进来"：它是 VS Code 扩展 + Java 服务，Tauri WebView 里跑不了；打包体积与轻量定位冲突 |
| **Spell Right（VS Code 扩展）** | Hunspell 词典 + 多语言 + 自定义词典（纯拼写，无语法） | 拼写 | 词典 ≈ 0.5MB/语言 | 低 | ✅ 架构可直接照搬：**词典层放 Rust** |
| nspell（JS，等价 Spell Right 的 JS 版） | JS 实现 Hunspell | 拼写 | ≈ 0.5MB/语言 | 低 | ⚠️ 大文档在主线程逐词检查有卡顿风险；LaTeX 掩码仍要自写 |

**Rust 侧证据（spellbook）**：`helix-editor/spellbook`，**MPL-2.0**，`no_std`、仅依赖 hashbrown；API `Dictionary::new(&aff, &dic)` / `dict.check(word) -> bool` / `dict.suggest(word, &mut out)`；Helix 编辑器在用，Zed 的 codebook 与 cargo-spellcheck 也在用；en_US 词典在仓库内自带。

**结论（推荐组合）**

1. **默认后端 = spellbook + 随包 `en_US.aff/.dic`**（"Spell Right 的架构"）：Rust 侧只暴露一个批量查词命令，词典用 `OnceLock` 常驻内存，避免每次读盘。
   - 新增命令：`spell_check_words(words: Vec<String>) -> Vec<MisspelledWord { word, suggestions: Vec<String> }>`
   - **位置计算留在 TS**（`tokenizeText` 已有 from/to），Rust 只回答"这个词对不对、建议是什么"——接口最小、IPC 数据量小（去重词表，通常几百个）。
2. **LaTeX 感知的掩码仍是必须自研的部分**（两家都没法直接白送）：跳过命令名、数学区、verbatim 类环境、`\cite/\ref/\label/\url/\href/\includegraphics/\input` 参数、URL/路径/邮箱、全大写缩写、CJK。这一层放 `src/editor/spell/tokenizeText.ts`，纯函数可 node 单测。
3. **LTeX+ 的能力用"可选外部后端"承接（M2-4e，P3，不阻塞本期）**：设置里填 LanguageTool HTTP 地址（用户自建本机 Java 服务或远程），Zetla 把**当前段落**POST 到 `/v2/check`，把 `matches` 映射成 CM6 诊断与快速修复。这样能吃到语法/标点/中文规则，又不用打包 JRE；LTeX+ 的 `ltex.latex.commands` 那套语义由我们自己的掩码 + `\cite` 白名单近似覆盖。
4. **中文拼写仍不做**（Hunspell 无中文词典）；中文相关能力只在 M2-4e 的 LanguageTool 后端下出现。

**为什么不让词典留在前端（nspell）**：三个理由——① tex-fmt 已经把 Rust 后端拉起来了，词典放同侧可复用编码/EOL/路径处理；② 完整 Hunspell affix 解析在 JS 里对 10 万词文档有可感知卡顿；③ 将来若加多语言词典（de/fr），Rust 侧只是加文件，前端不动。

### M2-4d（可选）格式化规则可配置 + diff 预览

### M2-4e（可选 · P3+）LanguageTool HTTP 外部后端

- 设置：`spell.languageToolUrl`（空=不用）+ 语言（en-US / zh-CN）

## 4. 配置口径（TS ↔ Rust 同步）

```ts
// src/types/settings.ts
format: {
  tabsize: 2 | 4;          // 环境缩进宽度，默认 2
  usetabs: boolean;        // 用 Tab 缩进，默认 false
  wrap: boolean;           // 长行包裹（会重排正文，默认 false）
  wraplen: number;         // wrap=true 时的目标列宽，默认 100（40–160）
  formatTables: boolean;   // 表格 & 对齐（会重排表格，默认 false）
};
spell: {
  enabled: boolean;        // 默认 false
  language: "en-US";       // 词典语言（本期仅 en-US）
  words: string[];         // 自定义词表（小写/去重/上限 2000）
  languageToolUrl: string; // M2-4e：空=不启用外部后端
};
```

- Rust 侧 `FormatConfig` / `SpellConfig`（`camelCase` + `default`），`normalize()`：`tabsize ∈ {2,4}`、`wraplen` 钳制 40–160、`words` 去空白/小写/去重/截断 2000、`language` 白名单、`languageToolUrl` 仅接受 `http(s)://`；`camel_case_keys` 测试补断言。
- `DEFAULT_SETTINGS` 同步；`useSettingsEffects` 无需改（拼写开关由编辑器订阅）。

## 7. 风险与回退

| 风险 | 影响 | 处置 |
|---|---|---|
| tex-fmt 默认 wrap 切中文行 | diff 爆炸 | 默认 `wrap=false`；开关显式提示「会重排正文」 |
| tex-fmt `format_file` panic | 崩溃 | `catch_unwind` + 不写盘 + toast；单测覆盖 |
| 缩进风格冲突（作者 4 空格） | 大 diff | `tabsize` 开关 + 先提示「首次格式化建议先提交/备份」 |
| 选区跨环境边界 | 环境体错乱 | 扩展到环境边界并告知；选区在别的文件里起 `\begin` → 拒绝 |
| Rust 依赖树变大 | 构建变慢、包 +1~2MB | 若不可接受改 sidecar（§2.1 B），前端接口不变 |
| spellbook 是 alpha、MPL-2.0 | 误判/许可证 | 仅链接使用、不修改源码，About 里注明；误报用加入词典兜底；若质量不足可换 nspell（接口不变） |
| 拼写误报 | 干扰写作 | 默认关 + 阈值跳过 + 一键加入词典 |

**回退开关**：拼写默认关闭；格式化是显式命令，不进任何自动流程（保存/编译都不触发）。
