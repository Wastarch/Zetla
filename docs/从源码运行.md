# 从源码运行

> 本文档从 README 抽离，涵盖构建环境、打包、版本号与测试、目录结构。返回 [README](../README.md)。

## 环境要求

- **Node.js 20+**（Vite 8 要求）
- **Rust stable** 与 Cargo
- **Visual Studio 2022 Build Tools**，包含 MSVC 和 Windows SDK

```powershell
git clone https://github.com/Wastarch/Zetla.git
cd Zetla
npm install
npm run tauri dev
```

首次启动需要编译 Rust 后端，耗时会比后续启动长。

> 如果 `cargo` 找不到 `link.exe`，请在 “Developer PowerShell for VS 2022” 中运行构建命令。

## 构建安装包

正式包使用 **Inno Setup 6**（需本机安装 Inno Setup；编译器 `ISCC.exe` 会自动从注册表/常见目录查找，也可用 `INNO_SETUP_ISCC` 指定）：

```powershell
# 1) 只编 release exe（不触发 NSIS 下载）
npm run tauri build -- --no-bundle

# 2) 调 ISCC 生成安装包
npm run package:inno
```

也可以一步完成：

```powershell
npm run package:win
```

安装包输出到：

```text
build/installer/Zetla_<version>_x64-setup.exe
```

版本号唯一源是 `package.json` 的 `version` 字段：`scripts/sync-version.mjs` 会在每次 `dev`/`build`/`tauri` 前自动把它同步到 `tauri.conf.json`、`Cargo.toml` 与前端 `src/version.ts`，安装包名随之切换（详见[版本号管理](#版本号管理)）。安装脚本在 `src-tauri/windows/inno/zetla.iss`。卸载时会读取 `%LOCALAPPDATA%\Zetla\tex-install.txt` 与 `<texdir>\.zetla-tex`，询问是否同时删除 Zetla 代装的 TeX Live（默认保留，静默卸载一律保留）。

> NSIS 配置仍保留在 `tauri.conf.json` / `windows/nsis-hooks.nsh` 作为备用，但正式发布不再使用。

**Linux / macOS 构建（CI）**：两个手动触发的工作流 —— `.github/workflows/build-linux.yml`（Actions 页选 `Build Linux`，可指定 `deb appimage rpm` 组合）与 `.github/workflows/build-macos.yml`（`Build macOS`，出 universal 的 `.app`/`.dmg` 与自动更新用的 `.app.tar.gz`）。两者都会额外产出 `SHA256SUMS` 随 artifact 上传；auto-update 清单由 `scripts/update-manifest.mjs` 生成（见[发版与更新清单](#发版与更新清单)）。`src-tauri/tauri.linux.conf.json` 在 Linux 构建时自动合并，将 `bundle.active` 置为 `true`；`src-tauri/tauri.macos.conf.json` 同理，并给出 ad-hoc 签名配置。

## 发版与更新清单

三平台产物后，用 `scripts/update-manifest.mjs` 一次生成仓库根 `latest.json`（客户端更新检测读它），替掉过去手改 version/url/sha256 的做法。

**1. 出产物**

| 平台 | 产出方式 | 产物（文件名必须含本次版本号） |
| --- | --- | --- |
| Windows | 本机 `npm run package:win` | `build/installer/Zetla_<ver>_x64-setup.exe` |
| Linux | Actions → `Build Linux`（`deb appimage rpm`） | `Zetla_<ver>_amd64.AppImage`、`zetla_<ver>_amd64.deb`、`*.rpm` |
| macOS | Actions → `Build macOS` | `Zetla_<ver>_universal.app.tar.gz`、`*.dmg` |

CI 的 artifact 解压到 `build/artifacts/`，Windows 包留在 `build/installer/`；脚本默认就扫这两处，以及本机 `src-tauri/target/.../bundle`（也可用 `--assets` 指定任意目录）。

**2. 生成清单**

```powershell
# 先干跑看一眼（不写文件）
node scripts/update-manifest.mjs --notes-text "新增 xxx" --dry-run

# 确认后落盘（幂等：同版本重跑内容不变则不写）
npm run release:manifest -- --notes-text "新增 xxx"

# 说明较长时从文件读（支持 ## 标题 / - 列表 / **粗体** 等轻量标记）
npm run release:manifest -- --notes docs/更新说明.md
```

清单结构（协议 v2）：

- **顶层 `installers`** 仍指向 Windows 包：老客户端（0.2.x / 0.3.0）只读这一项，删空会让它们误判「已是最新」。
- **`platforms`** 按平台键给条目：`windows-x86_64`（`kind=exe`）、`darwin-universal`（`kind=app-tar-gz`，arm64 与 x86_64 共用，客户端按 `darwin-*` → `darwin-universal` 回退）、`linux-x86_64`。
- `linux-x86_64` 可同时有 `installers`（AppImage，`kind=appimage`，应用内原地换包）与 `packages`（deb/rpm，只能下载后交系统安装器）；安装版用户 `env.canSelfUpdate=false`，客户端自动走 `packages`。
- 每个文件按默认基址生成 **Gitee + GitHub 两条源**，顺序即客户端回退顺序；换仓库改 `--base`。

**3. 发布**

把 `latest.json` 与全部产物一起传到 GitHub / Gitee 的 Release（tag = `v<ver>`），`latest.json` 另需同步提交到两边 main 分支（客户端从 raw 地址拉）。

要点：

- 清单里的 `sha256` 是**发布产物**的哈希，产物重打就必须重跑脚本 —— 否则客户端校验失败并回退到下一个源。
- 换版本必须给更新说明（脚本会直接报错），避免把上一版文案带到新版本。
- 缺少 Windows 包时脚本会沿用上一版顶层 `installers` 并告警，别在这种情况下发版。

## 版本号管理

版本号只需维护一处：**`package.json` 的 `version` 字段**。

```powershell
# 方式一：一条命令改版本并全量同步（推荐）
node scripts/sync-version.mjs 0.2.8

# 方式二：先手改 package.json 的 version，再同步
npm run version:sync
```

`npm run dev` / `build` / `tauri` 每次都会自动前置同步，日常开发无感知。同步落点如下，**请勿手改**：

| 落点 | 用途 |
| --- | --- |
| `src-tauri/tauri.conf.json` | Tauri 应用版本：关于页显示、安装包文件名 |
| `src-tauri/Cargo.toml`、`src-tauri/Cargo.lock` | Rust crate 版本 |
| `package-lock.json` | npm 锁文件根版本 |
| `src/version.ts` | 前端常量 `APP_VERSION`（生成文件） |

## 测试与检查

```powershell
# 前端类型检查
npx tsc --noEmit

# 前端生产构建
npm run build

# Rust 单元测试
cd src-tauri
cargo test
```

引用模块另有 Node 纯逻辑断言（需 Node 22+，逐个运行 `scripts/*.test.ts`）：

```powershell
node --experimental-strip-types scripts/cite-support.test.ts
```

## 目录结构

```text
Zetla/
├─ src/                 # React 前端：项目管理、编辑器、预览、引用、公式、表格、模板等
├─ src-tauri/           # Rust/Tauri 后端：编译、文件、配置、更新、安装器等
│  ├─ src/commands/     # Tauri commands
│  ├─ templates/        # 内置 6 套 LaTeX 模板（含宁夏大学学位论文）
│  └─ windows/inno/     # Inno Setup 正式包脚本
├─ scripts/             # 打包、版本同步与 Node 单元测试
├─ patches/             # 第三方依赖补丁（小地图宽度等）
├─ docs/                # 使用指南（模板编写、自定义编译流程）、更新日志与界面稿
│  └─ dev/              # 开发文档 / 开发计划 / 设计稿（.gitignore 忽略，仅本地）
├─ public/              # 静态资源（含 logo）
└─ build/               # 打包脚本与打包文档
```
