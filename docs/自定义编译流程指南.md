# Zetla 自定义编译流程指南（Tool / Recipe）

> 面向使用者的完整操作手册：怎么选流程、怎么改流程、怎么写自定义工具与条件。
> 设计稿与实现细节见 `docs/dev/compile-recipe-system.md`（开发目录，不入库）；README 的「自定义编译流程」一节是本文的速览版。
> 若本文与开发文档口径冲突，**以实际界面与后端行为为准**，并欢迎提 Issue 校正文档。

---

## 1. 这套机制解决什么问题

早期版本的编译流程是写死在程序里的：`latexmk` 优先，缺 Perl 时回退到引擎多遍直跑，另外允许配一组固定步骤。想加一步 `makeglossaries`、想换成 `bibtex`、想让某一步只在特定文件出现时才跑，都做不到。

现在编译流程由**数据**描述，分两层：

| 概念 | 含义 | 例子 |
| --- | --- | --- |
| **Tool（工具）** | 一条可执行命令 = 命令 + 参数 + 环境变量（+ 可选忽略错误） | `xelatex -synctex=1 ... main.tex`、`biber main` |
| **Recipe（流程）** | 有序的工具步骤列表（+ 条件、自动重跑、失败回退） | `XeLaTeX → biber（有 .bcf 才跑）→ XeLaTeX → XeLaTeX` |

编译一次就是「解析一个 Recipe → 逐步执行它的 Tool」。两个概念解耦后，同一个工具可以被多个流程复用，改流程不需要改程序。

**只做全局配置**：工具、流程、默认流程全部保存在 `%APPDATA%\Zetla\config.json` 的 `build` 段，**不会写进项目的 `.ltex/config.json`**。项目级只有主文件与引擎设置。

## 2. 快速开始（3 分钟）

1. 打开一个项目，点标签栏右上角的 **▶** 编译一次，确认默认链路能出 PDF。
2. 点 **▾**（▶ 右边的小箭头）→ 菜单里选 `engine-direct` → 立即按这个流程编译一次，日志首行会显示「流程 engine-direct」。
3. 再点 **▶**，仍然是 `engine-direct`：菜单选择的是**当前流程**，会一直跟随，直到你换一个或选「按默认流程编译」。
4. 想编排自己的流程：`Ctrl+,` → **编译设置** →「编译流程（Tool / Recipe）」→ 「+ 新建流程」→ 输入名字 → 「编辑步骤」→ 用下拉和 `↑↓` 调整顺序 → 「设为默认」→ **保存设置**。

> 「保存设置」之前所有改动都是草稿：编译会按草稿即时预览，但关掉设置页不保存就会回滚。

## 3. 三个入口与优先级

| 入口 | 操作 | 作用 |
| --- | --- | --- |
| 标签栏 **▶ \| ▾** | 左段 ▶ 编译 / 编译中终止；右段 ▾ 打开流程菜单 | 菜单选中即**切换当前流程**并立即编译一次 |
| 状态栏编译按钮 | **右键** 或 **长按约 0.5 秒** | 同一个菜单、同一份当前流程，行为完全一致 |
| 设置页 | `Ctrl+,` → 编译设置 → 编译流程 | 增删工具 / 流程、编辑步骤、设定**默认流程** |

一次编译时，流程按下面的顺序决定（前者优先）：

```text
菜单里刚选的当前流程（存在浏览器 localStorage）
    ↓ 没有
设置页的「默认编译流程」defaultRecipe
    ↓ 没有
老配置里的 build.steps（历史兼容，界面已无入口）
    ↓ 没有
内置 latexmk
```

- 「当前流程」存在 `localStorage` 键 `zetla.build.lastUsedRecipe`，**不写入配置文件**，重启应用仍在，卸载/清理浏览器数据后失效。
- 菜单首项「**按默认流程编译**」会清掉当前流程，本次与之后都回到设置页默认。
- 菜单末项「**管理编译流程…**」直接跳到 设置 → 编译设置。
- 当前流程指向的自定义流程若在设置页被删除，下次打开菜单会自动清除这个悬空选择。

`Ctrl+B`、保存时自动编译、实时预览同样跟随当前流程。

## 4. 内置流程与内置工具

### 4.1 两个内置流程（不可删、不可改）

| 名称 | 步骤 | 失败回退 |
| --- | --- | --- |
| `latexmk` | `latexmk`（按生效引擎自动加 `-xelatex` / `-pdflatex` / `-lualatex`，由它自己决定跑几遍） | `engine-direct` |
| `engine-direct` | 引擎 → `biber`（仅当 `%OUTDIR%/%DOCFILE%.bcf` 存在）→ 引擎 → 引擎 | 无 |

`engine-direct` 里的「引擎」是**真实引擎名**：全局引擎为「跟随项目（自动）」时显示 `XeLaTeX`，设为 pdfLaTeX 时显示 `pdfLaTeX`，以此类推。这就是原来「缺 Perl 时回退的多遍引擎管线」，现在以内置流程的形式存在。

`latexmk` 是 Perl 脚本：本机没有可用 Perl 或找不到 `latexmk` 时，会自动回退到 `engine-direct`，日志里能看到提示。

### 4.2 步骤可写的工具名

| 类别 | 可写的值 | 说明 |
| --- | --- | --- |
| 真实编译引擎 | `xelatex` / `pdflatex` / `lualatex` | 显示名 XeLaTeX / pdfLaTeX / LuaLaTeX。**选中即固定该引擎**，不受全局引擎设置影响；自动补 `-synctex=1 -interaction=nonstopmode -file-line-error <主文件名>` |
| 辅助工具 | `latexmk` / `biber` / `bibtex` | 本来就是真实命令名；`biber` / `bibtex` 默认参数为主文件名（无扩展名），本机没装时**跳过该步**而不算失败 |
| 兼容别名 | `latex` | 跟随当前生效引擎。**仅后端兼容老配置**，设置页下拉不再列出，新流程请写真实引擎名 |
| 自定义工具 | 你在「+ 新建工具」里起的名字 | 见 §5 |

命令先在 TeX 搜索目录（Zetla 独立 TeX 目录 + 系统 `PATH` + 常见安装位置）里找；找不到就当文件路径处理；都不是则该流程不可用并尝试回退。

## 5. Tool 字段

在设置页「+ 新建工具」只能填名字，完整字段要点开「**高级：JSON 编辑（完整字段）**」，把 `tools` 数组里的对象补全后点「应用 JSON」。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | string | 唯一名称，Recipe 通过它引用；不能和内置 token 重名 |
| `command` | string | 命令名、真实引擎 token 或可执行文件的完整路径 |
| `args` | string[] | 参数数组，**支持占位符**；引擎 / latexmk / biber 步会在内置参数之后追加这里的内容 |
| `cwd` | string \| null | 见下方「已知限制」——当前版本**尚未生效** |
| `env` | object | 注入子进程的环境变量，键值原样传入（不展开占位符） |
| `ignoreErrors` | boolean | `true` 时该步命令返回非 0 也不阻断后续步骤与整体成败，默认 `false` |

例：给引擎加 `-shell-escape`，并为外部脚本注入一个开关：

```json
{
  "name": "xelatex-shell",
  "command": "xelatex",
  "args": ["-shell-escape"],
  "cwd": null,
  "env": { "MY_BUILD_FLAG": "1" },
  "ignoreErrors": false
}
```

> `command` 写成引擎名时，仍由执行器补齐标准参数与 `%DOCFILE_EXT%`；`args` 里**不要**重复写主文件名，否则会传两遍。

## 6. Recipe 字段与 `when`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | string | 唯一名称；`latexmk` / `engine-direct` 为内置保留名，不能占用 |
| `tools` | array | 步骤数组；元素可以是工具名字符串，也可以是 `{ "tool": "...", "when": {...} }` |
| `repeat` | object \| null | `{ "untilStable": true, "max": 5 }`，见 §7 |
| `fallback` | string \| null | 另一个流程的名字，见 §7 |

`when` 条件**在每一步执行前即时求值**，不是一次性预判——所以「先跑一遍引擎生成 `.bcf`，再判断是否跑 biber」这类流程能正常工作。三种条件：

| type | 写法 | 判定 |
| --- | --- | --- |
| `fileExists` | `{ "type": "fileExists", "path": "%OUTDIR%/%DOCFILE%.bcf" }` | `path` 先展开占位符，再判断文件是否存在 |
| `logRegex` | `{ "type": "logRegex", "pattern": "Rerun" }` | 主引擎 `.log` **包含该子串**即成立 |
| `env` | `{ "type": "env", "name": "MY_FLAG", "value": "1" }` | 环境变量存在即成立；带 `value` 时要求值完全相等 |

> 字段名沿用设计稿叫 `logRegex`，但当前实现是**子串包含匹配，不是正则表达式**，`.*`、`|` 之类会被当普通字符。

设置页的步骤编辑器能增删步骤、上下移动、切换工具；带 `when` 的步骤会显示 `when` 标记，但**条件内容只能在 JSON 编辑器里编写**。

## 7. 自动重跑（`repeat`）与失败回退（`fallback`）

**`repeat.untilStable`**：流程跑完后，若主引擎 `.log` 里出现 `Rerun to get cross-references right`、`Label(s) may have changed`、`Package biblatex Warning` 等提示，就**只重跑流程里的引擎步**（`biber` / `bibtex` / 自定义工具不重跑），直到日志不再提示或达到 `max`。默认 `max = 10`，界面可设 1–100，`max` 是防死循环的硬上限。

**`fallback`**：只在「工具无法启动」时切换——命令找不到、`latexmk` 缺可用 Perl、子进程启动失败。执行器用已尝试集合防环，同一个流程不会被反复回退。

> **容易误解的一点**：源码编译报错（命令返回非 0）**不会**触发 `fallback`，它会直接把本次编译标记为失败。想让某一步失败不阻断，给那个 Tool 设 `ignoreErrors: true`。

## 8. 占位符

| 占位符 | 展开为 | 示例（`D:\work\proj\main.tex`，项目根 `D:\work\proj`） |
| --- | --- | --- |
| `%DOC%` | 主文件全路径（不含扩展名），`/` 分隔 | `D:/work/proj/main` |
| `%DOC_EXT%` | 主文件全路径（含扩展名） | `D:/work/proj/main.tex` |
| `%DOCFILE%` | 主文件名（不含扩展名） | `main` |
| `%DOCFILE_EXT%` | 主文件名（含扩展名） | `main.tex` |
| `%DIR%` | 主文件所在目录 | `D:/work/proj` |
| `%OUTDIR%` | 输出目录（当前 = 主文件目录） | `D:/work/proj` |
| `%AUXDIR%` | 辅助目录（当前 = 输出目录） | `D:/work/proj` |
| `%WORKSPACE_FOLDER%` | 项目根目录 | `D:/work/proj` |

每个占位符都有 `_W32` 变体（如 `%DIR_W32%` / `%DOC_W32%`），在 Windows 上输出 `\` 分隔，供 `makeindex`、批处理脚本等原生命令使用；非 Windows 下与普通版本相同。

**当前生效范围**：`Tool.args` 与 `when.fileExists.path` 会展开占位符；`command` / `cwd` / `env` 的值原样使用，未知 token 也原样保留。

## 9. 可直接粘贴的 JSON 示例

点开设置页「高级：JSON 编辑（完整字段）」，把下面任一段整体粘进去 → 「应用 JSON」→「保存设置」。注意应用会**整束覆盖**当前的 `tools` / `recipes` / `defaultRecipe`，建议先点「载入当前草稿」备份一份。

### 9.1 biblatex 完整流程（带条件与收敛重跑）

```json
{
  "tools": [],
  "recipes": [
    {
      "name": "my-biblatex",
      "tools": [
        "xelatex",
        { "tool": "biber", "when": { "type": "fileExists", "path": "%OUTDIR%/%DOCFILE%.bcf" } },
        "xelatex",
        "xelatex"
      ],
      "repeat": { "untilStable": true, "max": 5 },
      "fallback": "latexmk"
    }
  ],
  "defaultRecipe": "my-biblatex"
}
```

第一遍 XeLaTeX 生成 `.bcf` 后，`biber` 的条件才成立；`.log` 还提示 `Rerun` 时只重跑 XeLaTeX 步。

### 9.2 自定义工具：术语表 + 额外引擎参数

```json
{
  "tools": [
    {
      "name": "glossaries",
      "command": "makeglossaries",
      "args": ["%DOCFILE%"],
      "cwd": null,
      "env": {},
      "ignoreErrors": true
    },
    {
      "name": "xelatex-shell",
      "command": "xelatex",
      "args": ["-shell-escape"],
      "cwd": null,
      "env": { "MY_BUILD_FLAG": "1" },
      "ignoreErrors": false
    }
  ],
  "recipes": [
    {
      "name": "thesis-full",
      "tools": ["xelatex-shell", "glossaries", "biber", "xelatex-shell", "xelatex-shell"],
      "repeat": null,
      "fallback": "latexmk"
    }
  ],
  "defaultRecipe": "thesis-full"
}
```

`makeglossaries` 没装时不像 `biber` 那样自动跳过，会导致流程不可用并回退到 `latexmk`；设 `ignoreErrors: true` 只对「命令跑起来但返回非 0」有效。

### 9.3 条件步骤 + 固定 pdfLaTeX

```json
{
  "tools": [],
  "recipes": [
    {
      "name": "conditional-demo",
      "tools": [
        "pdflatex",
        { "tool": "bibtex", "when": { "type": "fileExists", "path": "%OUTDIR%/%DOCFILE%.aux" } },
        { "tool": "pdflatex", "when": { "type": "logRegex", "pattern": "Rerun" } }
      ],
      "repeat": null,
      "fallback": "engine-direct"
    }
  ],
  "defaultRecipe": "conditional-demo"
}
```

即使全局引擎是 XeLaTeX，这个流程也固定用 pdfLaTeX——流程里写真实引擎名即锁定引擎。

**JSON 校验规则**：根节点必须含 `tools`（数组）与 `recipes`（数组）；`defaultRecipe` 可省略或 `null`；流程名不能重复；`when.type` 只接受 `fileExists` / `logRegex` / `env`；`repeat.max` 必须是 ≥1 的数字。上限：工具 32 个、流程 32 个、单流程 32 步。JSON 非法时会显示红色错误，原配置不受影响。

## 10. 配置存在哪里

| 内容 | 位置 |
| --- | --- |
| `tools` / `recipes` / `defaultRecipe` | `%APPDATA%\Zetla\config.json` → `build` 段（**全局**） |
| 「当前流程」（菜单选的） | 浏览器 `localStorage` 键 `zetla.build.lastUsedRecipe` |
| 主文件、项目引擎 | 项目内 `.ltex/config.json`（**项目级，不含流程配置**） |
| 内置流程 | 不落盘，运行时生成 |

老配置里若还有 `build.steps`（早期版本的固定步骤序列），后端仍会静默合成一个兼容流程让它继续生效；设置页已不再有该编辑器。想彻底清理，手工从 `config.json` 删掉 `steps` 即可。

## 11. 排错清单

| 现象 | 检查 |
| --- | --- |
| 日志提示「未找到命令：xxx」 | 命令不在 TeX 搜索目录；把 `command` 写成 `PATH` 里能找到的名字或 exe 完整路径。该流程会尝试 `fallback` |
| `biber` / `bibtex` 步骤没跑 | 本机未安装时会被**跳过**（提示但不算失败）；装好 TeX 发行版后重试 |
| 带 `when` 的步骤没触发 | `fileExists` 的 `path` 是否用了 `%OUTDIR%`（产物在主文件同目录）；`logRegex` 是否写成了正则（当前只做子串匹配） |
| 编译一直重跑 | `repeat.max` 设小一点（如 3）；某些宏包会持续写 `Rerun` 提示 |
| 编译报错后没有走 `fallback` | 符合预期：`fallback` 只处理工具无法启动；源码错误请看日志面板 |
| 「应用 JSON」报红 | 按提示定位到具体字段（如 `recipes[0].tools[2].when.type`）；「载入当前草稿」可恢复 |
| 保存后自定义流程消失 | 确认点了设置页的「保存设置」；检查 `%APPDATA%\Zetla\config.json` 的 `build.recipes` 里是否有该流程 |
| 换了流程但编译日志没变 | 看日志首行的「流程 …」；菜单选的是当前流程，`Ctrl+B` 也会跟随 |

## 12. 已知限制

- `Tool.cwd` 字段可以保存，但**当前执行器尚未接入**：所有步骤的工作目录恒为主文件所在目录。需要特定工作目录时，请在命令 / 脚本里自行切换。
- 输出目录固定为主文件同目录，`%OUTDIR%` / `%AUXDIR%` 与 `%DIR%` 等价；项目设置里的「输出目录」仍是置灰的。
- `logRegex` 是子串包含匹配，不是正则；`env` 值与 `command` 不展开占位符。
- 内置流程只读；想改只能新建一个用户级流程，复制它的步骤后调整。
- `fallback` 不处理源码编译错误，也不保证 PDF 一定产出（最终仍按产物与 `.log` 判定成败）。
- 没有项目级流程配置，同一套流程作用于所有项目；可用「当前流程」按需要临时切换。
- 取消编译、重叠触发（latest-wins）、实时预览等既有行为不受流程编排影响。
