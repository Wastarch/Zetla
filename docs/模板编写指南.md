# 如何给 Zetla 新增一套 LaTeX 项目模板（实操指南）

> 本指南是 `docs/开发文档.md` §5「模板系统」的**实操落地版**，专门讲"怎么亲手写一套模板"。
> 若本指南与 `开发文档.md` 口径冲突，**以 `开发文档.md` 为准**；新增模板一般不需要改内核，按本指南照做即可。

---

## 1. 适用场景与核心机制

Zetla 的模板系统宗旨是：**项目结构由模板清单（manifest）声明，不硬编码**。新建项目时，内核只做"读清单 → 出表单 → 按结构生成文件"，它不假设任何项目类型（论文 / 简历 / 幻灯片 / 报告 / 书籍都行）。

新建项目链路：

```
list_templates()          → 扫描 src-tauri/templates/* 下每个子目录的 manifest.json
TemplateWizard（前端）     → 按 manifest.variables 动态渲染变量表单
create_project(id, vars, targetPath)  → 按 structure 生成文件 / 目录
```

**关键结论**：

- 新增一套模板 = 往 `src-tauri/templates/` 下加一个**文件夹**，里面放 `manifest.json` 和若干 `.tmpl` 模板文件。
- **无需改任何 Rust / TS 代码**（`list_templates` 是目录扫描，`create_project` 通用）。
- 打包自动包含（见 §7），开发期有 CWD 兜底。

---

## 2. 目录布局

一套模板就是一个子目录，目录名建议直接等于 manifest 里的 `id`：

```
src-tauri/templates/<模板id>/
├─ manifest.json              # 唯一真相源：元信息 + 编译配置 + 变量 + 文件结构
└─ <文件名>.tex.tmpl          # 模板正文（只有 .tmpl 会被渲染）
   └─ 子目录/<文件名>.tex.tmpl # 多文件模板可放子目录，由 manifest 的 source 指定相对路径
```

现有 5 套内置模板的真实布局（来自仓库）：

```
templates/
├─ article/                       # 单文件英文文档
│  ├─ manifest.json
│  └─ main.tex.tmpl
├─ ctex-cn/                       # 单文件中文文档
│  ├─ manifest.json
│  └─ main.tex.tmpl
├─ thesis-cn/                     # 多文件论文（ctexbook + 章节拆分）
│  ├─ manifest.json
│  ├─ main.tex.tmpl               # 内含 \input{chapters/...}
│  └─ chapters/{intro,related,method,conclusion}.tex.tmpl
├─ beamer-cn/                     # 多文件幻灯片（beamer + ctex）
│  ├─ manifest.json
│  ├─ main.tex.tmpl               # 内含 \usetheme{<%= theme %>}
│  └─ sections/{sec1,sec2}.tex.tmpl
└─ resume-cn/                     # 单文件简历（ctexart + 条件块）
   ├─ manifest.json
   └─ main.tex.tmpl               # 含 <% if jobtitle %>…<% endif %>
```

## 3. manifest.json 字段详解

```json
{
  "schemaVersion": "1.0",
  "id": "thesis-cn",
  "name": "中文毕业论文",
  "description": "多文件中文毕业论文骨架（ctexbook + 章节拆分 + 参考文献）",
  "category": "thesis",
  "tags": ["论文", "ctex", "多文件"],
  "version": "1.0",
  "build": { "engine": "xelatex", "mainFile": "main.tex", "outputDir": "build", "synctex": true },
  "dependencies": { "packages": ["ctex"], "assets": [] },
  "variables": [ /* 见 §4 */ ],
  "structure": {
    "dirs": ["chapters", "figures"],
    "files": [
      { "target": "main.tex", "source": "main.tex.tmpl", "render": true },
      { "target": "chapters/intro.tex", "source": "chapters/intro.tex.tmpl", "render": true }
    ]
  }
}
```

> ⚠️ **manifest 是 camelCase**（如 `schemaVersion` / `mainFile` / `outputDir`）。Rust 侧用 `#[serde(rename_all = "camelCase")]` 对应，写错大小写会解析失败或回退默认值。

| 字段 | 说明 |
|---|---|
| `schemaVersion` | 清单格式版本，用于未来兼容，固定 `"1.0"` |
| `id` | 模板唯一标识（建议与目录名一致） |
| `name` / `version` | 展示名 / 版本 |
| `description` / `category` / `tags` | **仅用于前端分组展示**，内核不据此分支 |
| `build.engine` | 编译引擎：`xelatex` / `pdflatex` / `lualatex` |
| `build.mainFile` | 编译入口（主文件） |
| `build.outputDir` | 产物目录（aux/pdf/log），默认 `build` |
| `build.synctex` | 是否启用源码↔PDF 同步 |
| `dependencies.packages` | 声明的系统宏包（环境检测 / 缺失提示用） |
| `dependencies.assets` | 随模板原样复制的 cls/sty/图片（**不渲染**） |
| `variables[]` | 表单变量（见 §4） |
| `structure.dirs[]` | 需要预创建的**空**目录（文件所在目录会自动创建，此处用于空目录） |
| `structure.files[]` | `target` 项目内路径、`source` 模板包内相对路径、`render` 是否渲染（见 §5） |

**设计原则**：

1. manifest 是项目结构的唯一真相源，内核不假设任何项目类型。
2. 领域相关字段（学校、学位、岗位、期刊名…）全部进 `variables`，schema 顶层不出现领域专有字段。
3. 内核**忽略未知键** → 模板可加自定义元数据，向前兼容。

## 4. 变量 `variables[]` 字段

每个变量对象支持的键：

| 键 | 作用 | 是否必填 |
|---|---|---|
| `key` | 变量名，模板里用 `<%= key %>` 引用 | 必填 |
| `label` | 前端表单显示名 | 必填 |
| `type` | `string` / `text` / `select` / `multiselect` / `bool` / `number` / `date` | 必填 |
| `required` | 是否必填 | 可选 |
| `default` | 默认值 / 表单初始化值 | 可选 |
| `options` | `select` / `multiselect` 的下拉选项数组 | select 必填 |
| `group` | 前端表单分组（折叠展示） | 可选 |
| `placeholder` | 输入框占位提示 | 可选 |
| `help` | 字段下方帮助说明 | 可选 |

各类型对应前端渲染（来自 `TemplateWizard.tsx`）：`text`→多行文本、`string`/`number`→单行输入、`select`→下拉、`bool`→勾选框、`date`→日期选择、`multiselect`→多选。

真实示例（节选自 `thesis-cn` / `resume-cn` / `beamer-cn`）：

```json
{ "key": "degree",    "label": "学位层次", "type": "select",
  "options": ["学士","硕士","博士"], "default": "硕士", "group": "基本信息" },
{ "key": "date",      "label": "提交日期", "type": "date", "group": "基本信息", "default": "2026-06" },
{ "key": "year",      "label": "毕业年份", "type": "number", "group": "基本信息", "default": 2026 },
{ "key": "withNotes", "label": "包含演讲备注页", "type": "bool", "default": false, "group": "外观" },
{ "key": "theme",     "label": "主题风格", "type": "select",
  "options": ["default","Madrid","Warsaw","AnnArbor","CambridgeUS"], "default": "Madrid", "group": "外观" }
```

## 5. 模板文件 `.tmpl` 语法（关键：避开 LaTeX 大括号）

### 5.1 变量替换

- 用 **ERB 风格 `<%= key %>`**。**禁止用 `{{var}}`**——LaTeX 里 `{{ }}` 太常见，会与模板引擎冲突。
- 缺失时回退顺序：`vars[key]` → manifest 的 `default` → 空串。
- 数字 / 布尔自动转字符串。

### 5.2 条件块（可嵌套）

```
<% if KEY %>…A…<% else %>…B…<% endif %>
```

- `else` 可省略；`if` 块可**嵌套**。
- 真值判定（`is_truthy`）：非空字符串 / 非零数字 / `true` / 非空数组为真；缺失或其余情况为假（走 `else`/空）。
- 真实示例（来自 `resume-cn`，`jobtitle` 为空则不渲染头衔行）：

```latex
{\LARGE <%= name %>}\\
<% if jobtitle %><%= jobtitle %>\\<% endif %>
<%= phone %> \quad <%= email %> \quad <%= address %>
```

### 5.3 渲染规则与保护

- 只有 `render: true` 的 `.tmpl` 才会被渲染；`dependencies.assets` 里的 cls/sty/图片一律**原样复制**。
- **未闭合保护**：未闭合的 `<%=` 或 `<%` 原样保留，不吞后续内容；`{{ }}` 与 LaTeX 原生语法不受影响。
- 不引入外部模板引擎（handlebars 等），自研约 60 行递归渲染器（`render_inner` + `split_if_block`），零依赖、易审计。

> ⚠️ **文件级 `condition` 字段当前（M2-3）未实现**：`structure.files[].condition` 现在会被忽略。整文件级别的"根据变量是否生成"暂时做不到，条件判断只能写在 `.tmpl` 内部的条件块里（见 5.2）。

## 6. 完整示例：新增一套「中文实验报告」模板 `report-cn`

### 6.1 `src-tauri/templates/report-cn/manifest.json`

```json
{
  "schemaVersion": "1.0",
  "id": "report-cn",
  "name": "中文实验报告",
  "description": "单文件中文实验报告骨架（ctexart）",
  "category": "report",
  "tags": ["报告", "实验", "ctex"],
  "version": "1.0",
  "build": { "engine": "xelatex", "mainFile": "main.tex", "outputDir": "build", "synctex": true },
  "dependencies": { "packages": ["ctex"], "assets": [] },
  "variables": [
    { "key": "title",     "label": "实验名称", "type": "string", "required": true, "group": "基本信息" },
    { "key": "author",    "label": "姓名",     "type": "string", "required": true, "group": "基本信息" },
    { "key": "studentId", "label": "学号",     "type": "string", "group": "基本信息" },
    { "key": "course",    "label": "课程",     "type": "string", "group": "基本信息", "default": "某某课程" },
    { "key": "withData",  "label": "含数据记录表", "type": "bool", "default": true, "group": "正文" },
    { "key": "conclusion","label": "实验结论", "type": "text", "group": "正文", "placeholder": "一句话总结" }
  ],
  "structure": {
    "dirs": [],
    "files": [
      { "target": "main.tex", "source": "main.tex.tmpl", "render": true }
    ]
  }
}
```

### 6.2 `src-tauri/templates/report-cn/main.tex.tmpl`

```latex
% 中文实验报告模板（由 Zetla 生成 · report-cn）
\documentclass{ctexart}
\title{<%= title %>}
\author{<%= author %><% if studentId %> \quad 学号：<%= studentId %><% endif %>}
\date{\today}

\begin{document}
\maketitle

\section*{课程信息}
课程：<%= course %>

\section*{实验目的}
请在此描述实验目的。

\section*{实验步骤}
请在此描述实验步骤。

<% if withData %>
\section*{数据记录}
请在此粘贴数据记录表。
<% endif %>

\section*{实验结论}
<%= conclusion %>

\end{document}
```

> 多文件版本只需把 `structure.dirs` 加上子目录、`structure.files` 多列几项 `render: true` 的 `.tmpl`，并在 `main.tex.tmpl` 里用 `\input{子目录/文件名}` 引用即可（参考 `thesis-cn`）。

## 7. 落地步骤

1. 在 `src-tauri/templates/` 下新建文件夹（建议用 `id` 命名）。
2. 写 `manifest.json`（camelCase）+ 一个或多个 `.tmpl` 文件，按 §3 / §4 / §5 填好。
3. **无需注册、无需改内核**——`list_templates` 自动扫描。
4. **打包自动包含**：`tauri.conf.json` 的 `bundle.resources` 是目录形式 `["templates"]`。
   - ⚠️ 不要写成 `templates/**` 尾缀 glob（会触发 tauri-build「未匹配任何文件」报错）。
   - 开发期兜底：`CWD/src-tauri/templates` 也能找到内置模板。
5. `npm run tauri dev` 起一次验证（见 §9）。

---

## 8. 已知限制与注意事项

| 项 | 说明 |
|---|---|
| 文件级 `condition` | 当前（M2-3）未实现，整文件条件生成做不到；条件只能写在 `.tmpl` 内部 |
| 占位符语法 | 必须用 `<%= %>`，**绝不用 `{{ }}`** |
| 路径安全 | 有 `safe_join` 防 `..` 穿越、`guard_id` 校验变量名，正常写相对路径即可 |
| camelCase | manifest 字段严格 camelCase，写错会解析失败 / 回退默认 |
| 不手改 bundle 落点 | 版本号唯一源是 `package.json`，模板随 `templates` 目录打包，勿在 `build/` 内改安装脚本 |
| 向后兼容 | 内核忽略未知键；旧模板无需迁移即可继续用 |

## 9. 验证清单

新建项目后用以下方式确认模板可用：

- [ ] `list_templates` 能列出你新增的模板（前端新建向导出现该模板）。
- [ ] 向导表单按 `variables[].type` / `group` 正确渲染（单行 / 多行 / 下拉 / 勾选 / 日期）。
- [ ] `create_project` 在目标目录生成了 `main.tex` 等文件，变量已正确替换。
- [ ] 条件块按变量真假正确生成 / 跳过（如 `withData=false` 时不出现数据记录表）。
- [ ] 生成的 `main.tex` 能正常编译（对应 `build.engine`）。
- [ ] 写入的 `.ltex/config.json` 含正确的 `engine` / `mainFile` / `outputDir` / `templateId`。

跑一次 `npm run tauri dev` 做无报错级自检即可。

## 10. 参考：现有 5 套内置模板一览

| 模板 id | 类型 | 文档类 | 文件数 | 特色 |
|---|---|---|---|---|
| `article` | 英文单文件 | `article` | 1 | 最基础，M0 起始模板 |
| `ctex-cn` | 中文单文件 | `ctexart` | 1 | 中文文档基础模板 |
| `thesis-cn` | 中文论文 | `ctexbook` | 5（含章节拆分） | 多 `select`/`date`/`number` 变量，章节 `\input` |
| `beamer-cn` | 中文幻灯片 | `beamer` | 3（含节拆分） | 含 `bool`（备注页）、`select`（主题） |
| `resume-cn` | 中文简历 | `ctexart` | 1 | 用条件块按 `jobtitle` 有无决定是否渲染头衔行 |

写新模板时，直接复制最接近的现有模板目录改是最快、最不易出错的方式。
